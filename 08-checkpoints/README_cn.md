# 检查点与回退（Checkpoints and Rewind）

检查点允许你保存对话状态并回退到 Claude Code 会话中的之前节点。这对于探索不同方法、从错误中恢复或比较替代方案来说非常有价值。

## 概述

检查点允许你保存对话状态并回退到之前节点，实现安全的实验和多方案探索。检查点是你对话状态的快照，包括：
- 所有交换的消息
- 已进行的文件修改
- 工具使用历史
- 会话上下文

在探索不同方法、从错误中恢复或比较替代解决方案时，检查点非常宝贵。

## 关键概念

| 概念 | 描述 |
|------|------|
| **检查点（Checkpoint）** | 对话状态的快照，包含消息、文件和上下文 |
| **回退（Rewind）** | 返回到之前的检查点，丢弃后续更改 |
| **分支点（Branch Point）** | 从该检查点开始探索多种方法 |

## 访问检查点

有两种主要方式访问和管理检查点：

### 使用键盘快捷键
按两次 `Esc`（`Esc` + `Esc`）打开检查点界面，浏览已保存的检查点。

### 使用斜杠命令
使用 `/rewind` 命令（别名：`/checkpoint`）快速访问：

```bash
# 打开回退界面
/rewind

# 或使用别名
/checkpoint
```

## 回退选项

回退时，你会看到包含五个选项的菜单：

1. **恢复代码和对话** -- 将文件和消息都恢复到该检查点
2. **恢复对话** -- 仅回退消息，保留当前代码不变
3. **恢复代码** -- 仅回退文件更改，保留完整对话历史
4. **从此处摘要** -- 将该点之后的对话压缩为 AI 生成的摘要，而不是丢弃它。原始消息保存在记录中。你可以选择提供说明，将摘要聚焦于特定主题。
5. **取消** -- 取消并返回到当前状态

## 自动检查点

Claude Code 会自动为你创建检查点：

- **每次用户提示** - 每次用户输入都会创建新检查点
- **持久性** - 检查点在会话间持续存在
- **自动清理** - 检查点在 30 天后自动清理

这意味着你可以随时回退到对话中的任何之前节点，从几分钟前到几天前都可以。

## 使用场景

| 场景 | 工作流程 |
|------|----------|
| **探索不同方法** | 保存 → 尝试 A → 保存 → 回退 → 尝试 B → 比较 |
| **安全重构** | 保存 → 重构 → 测试 → 若失败：回退 |
| **A/B 测试** | 保存 → 设计 A → 保存 → 回退 → 设计 B → 比较 |
| **错误恢复** | 发现问题 → 回退到最后良好状态 |

## 使用检查点

### 查看和回退

按两次 `Esc` 或使用 `/rewind` 打开检查点浏览器。你会看到所有可用检查点的列表及其时间戳。选择任意检查点即可回退到该状态。

### 检查点详情

每个检查点显示：
- 创建时的时间戳
- 已修改的文件
- 对话中的消息数量
- 使用过的工具

## 实际示例

### 示例 1：探索不同方法

```
用户：让我们给 API 添加缓存层

Claude：我来给你的 API 端点添加 Redis 缓存...
[在检查点 A 处进行更改]

用户：实际上，让我们试试内存缓存

Claude：我来回退以探索不同的方法...
[用户按 Esc+Esc 并回退到检查点 A]
[在检查点 B 处实现内存缓存]

用户：现在我可以比较两种方法了
```

### 示例 2：从错误中恢复

```
用户：重构认证模块以使用 JWT

Claude：我来重构认证模块...
[进行大量更改]

用户：等等，这破坏了 OAuth 集成。让我们回去。

Claude：我来帮你回退到重构之前...
[用户按 Esc+Esc 并选择重构前的检查点]

用户：这次让我们采用更保守的方法
```

### 示例 3：安全实验

```
用户：让我们尝试用函数式风格重写这个
[在实验前创建检查点]

Claude：[进行实验性更改]

用户：测试失败了。让我们回退。
[用户按 Esc+Esc 并回退到检查点]

Claude：我已经回退了更改。让我们尝试不同的方法。
```

### 示例 4：分支方法

```
用户：我想比较两种数据库设计
[记下检查点 - 称为"Start"]

Claude：我来创建第一个设计...
[实现 Schema A]

用户：现在让我回去尝试第二种方法
[用户按 Esc+Esc 并回退到"Start"]

Claude：现在我来实现 Schema B...
[实现 Schema B]

用户：太好了！现在我有两个 Schema 可以选择了
```

## 检查点保留

Claude Code 自动管理你的检查点：

- 每次用户提示都会自动创建检查点
- 旧检查点最多保留 30 天
- 检查点会自动清理以防止无限存储增长

## 工作流模式

### 用于探索的分支策略

当探索多种方法时：

```
1. 从初始实现开始 → 检查点 A
2. 尝试方法 1 → 检查点 B
3. 回退到检查点 A
4. 尝试方法 2 → 检查点 C
5. 比较 B 和 C 的结果
6. 选择最佳方法并继续
```

### 安全重构模式

进行重大更改时：

```
1. 当前状态 → 检查点（自动）
2. 开始重构
3. 运行测试
4. 若测试通过 → 继续工作
5. 若测试失败 → 回退并尝试不同方法
```

## 最佳实践

由于检查点是自动创建的，你可以专注于工作而不必担心手动保存状态。但请记住以下实践：

### 有效使用检查点

✅ **应该：**
- 回退前查看可用检查点
- 想要探索不同方向时使用回退
- 保留检查点以比较不同方法
- 理解每个回退选项的作用（恢复代码和对话、恢复对话、恢复代码或摘要）

❌ **不应该：**
- 仅依赖检查点来保存代码
- 期望检查点跟踪外部文件系统更改
- 将检查点作为 git 提交的替代品

## 配置

你可以在设置中切换自动检查点：

```json
{
  "autoCheckpoint": true
}
```

- `autoCheckpoint`：启用或禁用在每次用户提示时自动创建检查点（默认：`true`）

## 限制

检查点有以下限制：

- **Bash 命令更改不被跟踪** - 文件系统上的 `rm`、`mv`、`cp` 等操作不会被检查点捕获
- **外部更改不被跟踪** - 在 Claude Code 外部进行的更改（在你的编辑器、终端等中）不会被捕获
- **不替代版本控制** - 使用 git 进行对代码库的永久、可审计更改

## 故障排除

### 检查点丢失

**问题**：找不到预期的检查点

**解决方案**：
- 检查检查点是否被清除
- 验证 `autoCheckpoint` 在设置中已启用
- 检查磁盘空间

### 回退失败

**问题**：无法回退到检查点

**解决方案**：
- 确保没有未提交的更改冲突
- 检查检查点是否损坏
- 尝试回退到不同的检查点

## 与 Git 集成

检查点补充（但不替代）git：

| 功能 | Git | 检查点 |
|------|-----|--------|
| 范围 | 文件系统 | 对话 + 文件 |
| 持久性 | 永久 | 基于会话 |
| 粒度 | 提交 | 任意节点 |
| 速度 | 较慢 | 即时 |
| 共享 | 是 | 有限 |

同时使用两者：
1. 使用检查点进行快速实验
2. 使用 git 提交已完成的更改
3. 在 git 操作前创建检查点
4. 将成功的检查点状态提交到 git

## 快速入门指南

### 基本工作流

1. **正常工作** - Claude Code 自动创建检查点
2. **想回去？** - 按两次 `Esc` 或使用 `/rewind`
3. **选择检查点** - 从列表中选择要回退的位置
4. **选择恢复内容** - 选择恢复代码和对话、恢复对话、恢复代码、从此处摘要或取消
5. **继续工作** - 你已回到那个节点

### 键盘快捷键

- **`Esc` + `Esc`** - 打开检查点浏览器
- **`/rewind`** - 访问检查点的替代方式
- **`/checkpoint`** - `/rewind` 的别名

## 了解何时回退：上下文监控

检查点让你可以回去——但你怎么知道*何时*应该回退？随着对话增长，Claude 的上下文窗口会被填满，模型质量会悄然下降。你可能在不知情的情况下从一个半盲的模型获得代码。

**[cc-context-stats](https://github.com/luongnv89/cc-context-stats)** 通过在 Claude Code 状态栏添加实时**上下文区域**来解决这个问题。它跟踪你在上下文窗口中的位置——从**计划**（绿色，适合计划和编码）经**代码**（黄色，避免开始新计划）到**转储**（橙色，收尾并回退）。当你看到区域切换时，就知道是时候创建检查点并重新开始，而不是继续用质量下降的输出工作。

## 总结

检查点是 Claude Code 中的自动功能，让你可以安全地探索不同方法而不必担心丢失工作。每次用户提示都会自动创建新检查点，因此你可以回退到会话中的任何之前节点。

主要优势：
- 无畏地用多种方法进行实验
- 快速从错误中恢复
- 并排比较不同解决方案
- 与版本控制系统安全集成

记住：检查点不能替代 git。使用检查点进行快速实验，使用 git 进行永久代码更改。
