# 检查点示例

在 Claude Code 中有效使用检查点的真实案例。

注意：每次用户提示都会自动创建检查点，无需手动保存。要回退，请按两次 `Esc`（`Esc+Esc`）或使用 `/rewind` 打开检查点浏览器。

## 示例 1：数据库迁移

### 场景
你需要从 MySQL 迁移到 PostgreSQL，但想探索直接迁移和渐进式双写两种方法。

### 工作流程

```
用户：让我们实现从 MySQL 到 PostgreSQL 的直接迁移
      [自动创建检查点 A]

Claude：我来实现直接迁移...
[更改数据库驱动、更新查询、修改 Schema]

用户：运行测试
      [自动创建检查点 B]

Claude：运行测试...
❌ 15 个测试失败 - 连接池问题

用户：这种方法有问题。让我们试试双写模式。
[用户按 Esc+Esc，选择检查点 A，选择"恢复代码和对话"]

用户：现在实现一个同时写入两个数据库的双写模式

Claude：我来实现双写迁移...
[实现双写层、渐进式迁移策略]

用户：运行测试

Claude：运行测试...
✅ 所有测试通过

用户：双写方法显然更安全。让我们提交这个。
```

## 示例 8：使用从检查点摘要

### 场景
经过长时间调试后，你想压缩对话同时保留上下文。

### 工作流程

```
用户：[经过 20+ 条调试和探索消息后]

[用户按 Esc+Esc，选择早期检查点，选择"从此处摘要"]
[可选提供说明："关注我们尝试了什么以及什么奏效了"]

Claude：[从该点生成对话摘要]
[原始消息保存在记录中]
[摘要替换可见对话，减少上下文窗口使用]

用户：现在让我们继续有效的方法。
```

## 关键要点

1. **检查点是自动的**：每次用户提示都会创建检查点——无需手动保存
2. **使用 Esc+Esc 或 /rewind**：这是访问检查点浏览器的两种方式
3. **选择正确的恢复选项**：根据需要恢复代码、对话、两者或摘要
4. **不要害怕实验**：检查点让尝试激进更改变得安全
5. **与 git 结合**：使用检查点进行探索，git 用于最终完成的工作
6. **摘要长会话**：使用"从此处摘要"保持对话可管理
