# 钩子

一个视觉指南，了解事件驱动的自动化如何在工作流中执行自定义脚本。

> 📚 **关于本指南**
> 
> 本模块介绍 **Claude Code** 的钩子系统。
> 
> Kimi Code 用户可参考 **Kimi Code 适配**部分了解对应配置。

---

## 快速对照

| Claude Code | Kimi Code |
|-------------|-----------|

| 事件触发 | 事件触发 |
| 脚本执行 | 脚本执行 |

## 概览

钩子是在特定事件发生时自动执行的脚本，用于自动化验证、安全检查和工作流增强。

```
┌─────────────────────────────────────────────────────────────┐
│                     钩子架构                                 │
├─────────────────────────────────────────────────────────────┤
│                                                            │
│   事件触发                                                  │
│      │                                                     │
│      ├──▶ 文件保存                                         │
│      ├──▶ 命令执行                                         │
│      ├──▶ 会话开始/结束                                    │
│      └──▶ 自定义事件                                       │
│                     │                                      │
│                     ▼                                      │
│            ┌─────────────────┐                            │
│            │   钩子调度器    │                            │
│            └────────┬────────┘                            │
│                     │                                      │
│        ┌────────────┼────────────┐                       │
│        │            │            │                       │
│        ▼            ▼            ▼                       │
│   ┌─────────┐  ┌─────────┐  ┌─────────┐                 │
│   │pre-save │  │post-cmd │  │security │                 │
│   │ hook    │  │ hook    │  │ hook    │                 │
│   └────┬────┘  └────┬────┘  └────┬────┘                 │
│        │            │            │                       │

│   ┌─────────────────────────────────────┐               │

└─────────────────────────────────────────────────────────────┘
```

### 工作流程

```
事件发生 ──▶ 匹配钩子 ──▶ 执行脚本 ──▶ 反馈结果
```

## 安装

**Claude Code:**
```bash
# 创建钩子目录
mkdir -p ~/.claude/hooks

# 复制钩子脚本
cp pre-commit.sh ~/.claude/hooks/
cp security-check.sh ~/.claude/hooks/
chmod +x ~/.claude/hooks/*.sh
```

**Kimi Code 适配:**
```bash
# 创建钩子目录
mkdir -p ~/.kimi/hooks

# 复制钩子脚本
cp pre-commit.sh ~/.kimi/hooks/
cp security-check.sh ~/.kimi/hooks/
chmod +x ~/.kimi/hooks/*.sh
```

## 钩子模板

### Pre-Save Hook

```bash
#!/bin/bash
# ~/.claude/hooks/pre-save.sh 或 ~/.kimi/hooks/pre-save.sh
# 在文件保存前执行

FILE="$1"

# 检查文件类型
if [[ "$FILE" == *.js ]] || [[ "$FILE" == *.ts ]]; then
    # 运行 linter
    if ! eslint "$FILE"; then
        echo "❌ ESLint 检查失败"
        exit 1
    fi
    
    # 运行类型检查
    if ! npx tsc --noEmit; then
        echo "❌ 类型检查失败"
        exit 1
    fi
fi

echo "✅ 预保存检查通过"
exit 0
```

### Security Check Hook

```bash
#!/bin/bash
# ~/.claude/hooks/security-check.sh 或 ~/.kimi/hooks/security-check.sh
# 安全检查钩子

FILE="$1"

# 检查敏感信息泄露
if grep -E "(password|secret|token|key)\s*=\s*[\"'][^\"']+[\"']" "$FILE" 2>/dev/null; then
    echo "⚠️  警告：检测到可能的硬编码凭证"
    echo "请使用环境变量或密钥管理服务"
    exit 1
fi

# 检查危险函数
if grep -E "(eval|exec|system)\s*\(" "$FILE" 2>/dev/null; then
    echo "⚠️  警告：检测到危险函数调用"
    echo "请审查安全风险"
fi

echo "✅ 安全检查通过"
exit 0
```

## 工作原理

### 钩子执行流程

```
┌─────────────────────────────────────────────────────────────────┐
│                    钩子执行流程                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                │
│   1. 事件触发                                                   │
│            │                                                    │
│            ▼                                                    │
│   ┌─────────────────┐                                           │
│   │   事件类型识别  │ 例如：file-save、command-complete        │
│   └────────┬────────┘                                           │
│            │                                                    │
│            ▼                                                    │
│   2. 钩子发现                                                   │
│            │                                                    │
│            ├─▶ 扫描 ~/.claude/hooks/ 或 ~/.kimi/hooks/          │
│            │                                                    │
│            ├─▶ 匹配事件类型：pre-save.sh                        │
│            │                                                    │
│            ▼                                                    │
│   3. 执行钩子                                                   │
│            │                                                    │
│            ├─▶ 按字母顺序排序钩子                               │
│            │                                                    │
│            ├─▶ 传递上下文参数（文件路径、命令等）               │
│            │                                                    │
│            ├─▶ 执行脚本                                         │
│            │                                                    │
│            ▼                                                    │
│   4. 结果处理                                                   │
│            │                                                    │
│            ├─▶ 退出码 0：成功，继续操作                         │
│            │                                                    │
│            ├─▶ 退出码非 0：失败，阻止操作（如果是 pre-* 钩子）  │
│            │                                                    │
│            ├─▶ 输出捕获并显示给用户                             │
│            │                                                    │
│            ▼                                                    │
│   5. 完成                                                       │
│                                                                │
└─────────────────────────────────────────────────────────────────┘
```

## Kimi Code 适配

### 配置路径

| 配置项 | Claude Code | Kimi Code |
|--------|-------------|-----------|
| 钩子目录 | `~/.claude/hooks/` | `~/.kimi/hooks/` |
| 脚本格式 | Shell/Python/可执行文件 | Shell/Python/可执行文件 |
| 执行方式 | 事件触发 | 事件触发 |
| 退出码含义 | 0=成功，非0=失败 | 0=成功，非0=失败 |

### 快速迁移

```bash
# 1. 创建 Kimi Code 钩子目录
mkdir -p ~/.kimi/hooks

# 2. 复制钩子脚本
cp ~/.claude/hooks/* ~/.kimi/hooks/

# 3. 确保脚本可执行
chmod +x ~/.kimi/hooks/*.sh
```

### 注意事项

- 钩子脚本格式和逻辑完全相同
- 可以共享相同的钩子脚本
- 事件类型和触发机制相似
- 脚本可以检测运行环境并适配

## 最佳实践

| 实践 | 原因 | 示例 |
|------|------|------|
| **快速执行** | 不阻塞用户 | 钩子应在几秒内完成 |
| **清晰输出** | 用户知道发生了什么 | 使用 emoji 和颜色 |
| **可配置** | 适应不同项目 | 支持 .env 配置 |
| **优雅失败** | 不破坏工作流 | 提供绕过选项 |
| **文档化** | 团队理解 | 脚本头部注释 |

---

## 故障排除

| 问题 | 检查 | 解决方案 |
|------|------|---------|
| 钩子未执行 | 目录位置 | 确保在 `~/.claude/hooks/` 或 `~/.kimi/hooks/` |
| 权限错误 | 执行权限 | 运行 `chmod +x hook.sh` |
| 脚本错误 | 语法 | 使用 shellcheck 检查 |
| 阻塞工作流 | 执行时间 | 优化脚本或改为异步 |
