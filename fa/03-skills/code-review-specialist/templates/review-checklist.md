# چک‌لیست بازبینی کد

## چک‌لیست امنیت
- [ ] بدون اعتبارنامه یا رمز جاسازی‌شده
- [ ] اعتبارسنجی ورودی برای همه ورودی‌های کاربر
- [ ] جلوگیری از تزریق SQL (پرس‌وجوهای پارامتری)
- [ ] محافظت CSRF در عملیات‌های تغییردهنده حالت
- [ ] جلوگیری از XSS با فرار مناسب
- [ ] بررسی احراز هویت در نقاط پایانی محافظت‌شده
- [ ] بررسی مجوزدهی روی منابع
- [ ] درهم‌سازی امن گذرواژه (bcrypt، argon2)
- [ ] بدون داده حساس در لاگ‌ها
- [ ] الزام HTTPS

## چک‌لیست کارایی
- [ ] بدون پرس‌وجوی N+1
- [ ] استفاده مناسب از ایندکس‌ها
- [ ] کش کردن در جایی که سودمند است پیاده‌سازی شده
- [ ] بدون عملیات مسدودکننده روی رشته اصلی
- [ ] استفاده صحیح از async/await
- [ ] مجموعه‌داده‌های بزرگ صفحه‌بندی شده‌اند
- [ ] اتصال‌های پایگاه داده استخر (pool) شده‌اند
- [ ] عبارات باقاعده بهینه‌سازی شده‌اند
- [ ] بدون ساخت شیء غیرضروری
- [ ] جلوگیری از نشت حافظه

## چک‌لیست کیفیت
- [ ] توابع کمتر از ۵۰ خط
- [ ] نام‌گذاری شفاف متغیرها
- [ ] بدون کد تکراری
- [ ] مدیریت خطای مناسب
- [ ] توضیحات «چرایی» را بیان می‌کنند، نه «چیستی»
- [ ] بدون console.log در محیط تولید
- [ ] بررسی نوع (TypeScript/JSDoc)
- [ ] رعایت اصول SOLID
- [ ] الگوهای طراحی به‌درستی اعمال شده‌اند
- [ ] کد خودمستند

## چک‌لیست تست
- [ ] تست‌های واحد نوشته شده
- [ ] موارد مرزی پوشش داده شده
- [ ] سناریوهای خطا تست شده‌اند
- [ ] تست‌های یکپارچگی موجودند
- [ ] پوشش بیش از ۸۰٪
- [ ] بدون تست‌های ناپایدار (flaky)
- [ ] ماک کردن وابستگی‌های خارجی
- [ ] نام‌های شفاف برای تست‌ها
