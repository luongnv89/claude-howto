# مشارکت در Claude How To

از علاقه شما به مشارکت در این پروژه سپاسگزاریم! این راهنما به شما کمک می‌کند تا بدانید چگونه به‌طور مؤثر مشارکت کنید.

## درباره این پروژه

Claude How To یک راهنمای تصویری و مثال‌محور برای Claude Code است. ما ارائه می‌دهیم:
- **نمودارهای Mermaid** که توضیح می‌دهند قابلیت‌ها چگونه کار می‌کنند
- **قالب‌های آماده تولید** که می‌توانید فوراً استفاده کنید
- **مثال‌های دنیای واقعی** همراه با زمینه و بهترین شیوه‌ها
- **مسیرهای یادگیری تدریجی** از مبتدی تا پیشرفته

## انواع مشارکت

### ۱. مثال‌ها یا قالب‌های جدید
برای قابلیت‌های موجود (دستورات اسلش، مهارت‌ها، هوک‌ها و غیره) مثال اضافه کنید:
- کد آماده کپی-چسباندن
- توضیح شفاف درباره نحوه کار
- موارد استفاده و مزایا
- نکات اشکال‌زدایی

### ۲. بهبود مستندات
- شفاف‌سازی بخش‌های گیج‌کننده
- رفع غلط‌های تایپی و دستوری
- افزودن اطلاعات مفقود
- بهبود مثال‌های کد

### ۳. راهنماهای قابلیت
برای قابلیت‌های جدید Claude Code راهنما بسازید:
- آموزش‌های گام‌به‌گام
- نمودارهای معماری
- الگوها و ضدالگوهای رایج
- گردش کارهای دنیای واقعی

### ۴. گزارش اشکال
مسائلی که با آن‌ها روبه‌رو می‌شوید را گزارش دهید:
- توضیح دهید چه انتظاری داشتید
- توضیح دهید در واقع چه رخ داد
- گام‌های بازتولید را بنویسید
- نسخه مرتبط Claude Code و سیستم‌عامل را اضافه کنید

### ۵. بازخورد و پیشنهاد
به بهبود راهنما کمک کنید:
- توضیحات بهتر پیشنهاد دهید
- شکاف‌های پوشش را نشان دهید
- بخش‌های جدید یا بازسازمان‌دهی را توصیه کنید

### ۳. آماده‌سازی محیط

هوک‌های پیش از کامیت همان بررسی‌های CI را به‌صورت محلی پیش از هر کامیت اجرا می‌کنند. هر پنج بررسی باید پیش از پذیرش PR موفق شوند.

**وابستگی‌های لازم:**

```bash
# ابزارهای پایتون (uv مدیر بسته این پروژه است)
pip install uv
uv venv
source .venv/bin/activate
uv pip install -r scripts/requirements-dev.txt

# لینتر Markdown (Node.js)
npm install -g markdownlint-cli

# نمودارهای Mermaid با Pele رندر می‌شوند که به Node.js >= 20 نیاز دارد (چیزی
# لازم نیست سراسری نصب شود). نسخه خود را بررسی کنید:
node --version

# نصب pre-commit و فعال‌سازی هوک‌ها
uv pip install pre-commit
pre-commit install
```

**تأیید آماده‌سازی:**

```bash
pre-commit run --all-files
```

اجرای نخست، Node.js 22 را برای هوک‌های Mermaid دانلود می‌کند (pre-commit آن را فراهم می‌کند، بنابراین حتی بدون Node.js سیستمی هم کار می‌کنند) و بسته‌های Pele را در `scripts/.vendor-cache/pele/` قرار می‌دهد؛ اجراهای بعدی به‌صورت آفلاین کار می‌کنند. هوک‌های Mermaid در حالت سخت‌گیرانه اجرا می‌شوند و اگر Pele اجرا نشود شکست می‌خورند. برای کامیت آفلاین پیش از آن دانلود نخست، آن‌ها را با `SKIP=mermaid,vietnamese-mermaid,japanese-mermaid` رد کنید.

هوک‌هایی که در هر کامیت اجرا می‌شوند عبارت‌اند از:

| هوک | چه چیزی را بررسی می‌کند |
|------|---------------|
| `markdown-lint` | قالب‌بندی و ساختار مارک‌داون |
| `cross-references` | پیوندهای نسبی، لنگرها، بلوک‌های کد |
| `mermaid-syntax` | همه بلوک‌های ` ```mermaid ` به‌درستی تجزیه می‌شوند |
| `link-check` | نشانی‌های خارجی در دسترس هستند |
| `build-epub` | EPUB بدون خطا تولید می‌شود (در تغییرات `.md`) |

## دستورالعمل‌های نوشتار

### سبک مارک‌داون
- از سرتیترهای شفاف استفاده کنید (H2 برای بخش‌ها، H3 برای زیربخش‌ها)
- بندها را کوتاه و متمرکز نگه دارید
- برای فهرست‌ها از نکته‌های گلوله‌ای استفاده کنید
- بلوک‌های کد را با مشخص کردن زبان بنویسید
- بین بخش‌ها خط خالی بگذارید

### مثال‌های کد
- مثال‌ها را آماده کپی-چسباندن کنید
- منطق غیربدیهی را توضیح دهید
- نسخه‌های ساده و پیشرفته را هر دو بگنجانید
- موارد استفاده دنیای واقعی را نشان دهید
- مسائل بالقوه را برجسته کنید

### مستندسازی
- «چرایی» را توضیح دهید، نه فقط «چیستی»
- پیش‌نیازها را بگنجانید
- بخش‌های اشکال‌زدایی اضافه کنید
- به موضوعات مرتبط پیوند دهید
- آن را برای مبتدیان قابل فهم نگه دارید

### JSON/YAML
- از تودرتویی مناسب استفاده کنید (۲ یا ۴ فاصله، به‌طور یکنواخت)
- توضیحاتی برای پیکربندی اضافه کنید
- مثال‌های اعتبارسنجی را بگنجانید

### نمودارها
- در صورت امکان از Mermaid استفاده کنید
- نمودارها را ساده و خوانا نگه دارید
- زیر نمودارها توضیح بنویسید
- به بخش‌های مرتبط پیوند دهید

## دستورالعمل‌های کامیت

از قالب کامیت متعارف پیروی کنید:
```
type(scope): description

[optional body]
```

انواع:
- `feat`: قابلیت یا مثال جدید
- `fix`: رفع اشکال یا اصلاح
- `docs`: تغییرات مستندات
- `refactor`: بازساختاردهی کد
- `style`: تغییرات قالب‌بندی
- `test`: افزودن یا تغییر تست
- `chore`: ساخت، وابستگی‌ها و غیره

مثال‌ها:
```
feat(slash-commands): Add API documentation generator
docs(memory): Improve personal preferences example
fix(README): Correct table of contents link
docs(skills): Add comprehensive code review skill
```

## فرایند Pull Request

1. **PR را با توضیح شفاف بسازید**:
   - این تغییر چه چیزی اضافه/رفع می‌کند؟
   - چرا لازم است؟
   - مسائل مرتبط (در صورت وجود)

2. **جزئیات مرتبط را بگنجانید**:
   - قابلیت جدید؟ موارد استفاده را بگنجانید
   - مستندات؟ بهبودها را توضیح دهید
   - مثال‌ها؟ قبل/بعد را نشان دهید

3. **به مسائل پیوند دهید**:
   - از `Closes #123` برای بستن خودکار مسائل مرتبط استفاده کنید

4. **در بازبینی شکیبا باشید**:
   - نگهداران ممکن است بهبودهایی پیشنهاد دهند
   - بر اساس بازخورد تکرار کنید
   - تصمیم نهایی با نگهداران است

## امنیت

هنگام مشارکت در مثال‌ها و مستندات، لطفاً شیوه‌های کدنویسی ایمن را رعایت کنید:
