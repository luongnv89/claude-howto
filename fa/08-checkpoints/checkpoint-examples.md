# نمونه‌های چک‌پوینت

نمونه‌های واقعی از استفاده مؤثر از چک‌پوینت‌ها در Claude Code.

توجه: چک‌پوینت‌ها با هر پرامپت کاربر به‌صورت خودکار ساخته می‌شوند. نیازی به ذخیره دستی آن‌ها نیست. برای بازگشت، دو بار `Esc` را بزنید (`Esc+Esc`) یا از `/rewind` برای باز کردن مرورگر چک‌پوینت استفاده کنید.

## نمونه ۱: مهاجرت پایگاه داده

### سناریو
باید از MySQL به PostgreSQL مهاجرت کنید، اما می‌خواهید هم مهاجرت مستقیم و هم رویکرد تدریجی نوشتن دوگانه را بررسی کنید.

### گردش کار

```
کاربر: بیایید مهاجرت مستقیم از MySQL به PostgreSQL را پیاده‌سازی کنیم
      [چک‌پوینت A به‌صورت خودکار ساخته شد]

Claude: مهاجرت مستقیم را پیاده‌سازی می‌کنم...
[درایور پایگاه داده را تغییر می‌دهد، پرس‌وجوها را به‌روزرسانی می‌کند، طرح‌واره را تغییر می‌دهد]

کاربر: تست‌ها را اجرا کن
      [چک‌پوینت B به‌صورت خودکار ساخته شد]

Claude: در حال اجرای تست‌ها...
❌ ۱۵ تست شکست خورد - مشکلات استخر اتصال

کاربر: این رویکرد مشکل دارد. بیایید الگوی نوشتن دوگانه را امتحان کنیم.
[کاربر Esc+Esc را می‌زند، چک‌پوینت A را انتخاب می‌کند، «بازگردانی کد و گفت‌وگو» را برمی‌گزیند]

کاربر: حالا الگوی نوشتن دوگانه را پیاده‌سازی کن که در هر دو پایگاه داده می‌نویسد

Claude: مهاجرت نوشتن دوگانه را پیاده‌سازی می‌کنم...
[لایه نوشتن دوگانه و راهبرد مهاجرت تدریجی را پیاده‌سازی می‌کند]

کاربر: تست‌ها را اجرا کن

Claude: در حال اجرای تست‌ها...
✅ همه تست‌ها موفق

کاربر: رویکرد نوشتن دوگانه قطعاً ایمن‌تر است. بیایید این را کامیت کنیم.
```

## نکات کلیدی

1. **چک‌پوینت‌ها خودکار هستند**: هر پرامپت کاربر یک چک‌پوینت می‌سازد — نیازی به ذخیره دستی نیست
2. **از Esc+Esc یا /rewind استفاده کنید**: این دو راه دسترسی به مرورگر چک‌پوینت هستند
3. **گزینه بازگردانی درست را انتخاب کنید**: بسته به نیازتان کد، گفت‌وگو، هر دو یا خلاصه را بازگردانید
4. **از آزمایش نترسید**: چک‌پوینت‌ها انجام تغییرات بنیادی را ایمن می‌کنند
5. **با git ترکیب کنید**: از چک‌پوینت‌ها برای کاوش و از git برای کار نهایی استفاده کنید
6. **نشست‌های طولانی را خلاصه کنید**: از «خلاصه کردن از اینجا» برای قابل مدیریت نگه داشتن گفت‌وگوها استفاده کنید
