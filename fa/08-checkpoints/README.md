# چک‌پوینت‌ها و بازگردانی

چک‌پوینت‌ها به شما امکان می‌دهند وضعیت مکالمه را ذخیره کنید و در نشست Claude Code به نقاط قبلی بازگردید. این قابلیت برای کاوش رویکردهای مختلف، بازیابی از خطاها یا مقایسه راه‌حل‌های جایگزین بسیار ارزشمند است.

## مروری کلی

چک‌پوینت‌ها به شما امکان می‌دهند وضعیت مکالمه را ذخیره کنید و به نقاط قبلی بازگردید و به این ترتیب آزمایش و کاوش ایمن چندین رویکرد را ممکن می‌سازند. آن‌ها تصویری لحظه‌ای از وضعیت مکالمه شما هستند، شامل:
- تمام پیام‌های رد و بدل شده
- تغییرات اعمال‌شده در فایل‌ها
- تاریخچه استفاده از ابزارها
- زمینه نشست

چک‌پوینت‌ها هنگام کاوش رویکردهای مختلف، بازیابی از خطاها یا مقایسه راه‌حل‌های جایگزین بسیار ارزشمند هستند.

## مفاهیم کلیدی

| مفهوم | توضیحات |
|---------|-------------|
| **چک‌پوینت** | تصویری لحظه‌ای از وضعیت مکالمه شامل پیام‌ها، فایل‌ها و زمینه |
| **بازگردانی** | بازگشت به یک چک‌پوینت قبلی و کنار گذاشتن تغییرات بعدی |
| **نقطه شاخه** | چک‌پوینتی که از آن چند رویکرد مختلف کاوش می‌شود |

## دسترسی به چک‌پوینت‌ها

می‌توانید به دو روش اصلی به چک‌پوینت‌ها دسترسی داشته باشید و آن‌ها را مدیریت کنید:

### استفاده از میان‌بر صفحه‌کلید
دو بار `Esc` را فشار دهید (`Esc` + `Esc`) تا رابط چک‌پوینت باز شود و چک‌پوینت‌های ذخیره‌شده را مرور کنید.

### استفاده از دستور اسلش
برای دسترسی سریع از دستور `/rewind` (نام‌های مستعار: `/checkpoint`، `/undo`) استفاده کنید:

```bash
# باز کردن رابط بازگردانی
/rewind

# یا استفاده از نام مستعار
/checkpoint
```

## گزینه‌های بازگردانی

هنگام بازگردانی، فهرستی از شش گزینه به شما نمایش داده می‌شود:

1. **بازیابی کد و مکالمه** -- بازگرداندن هم فایل‌ها و هم پیام‌ها به آن چک‌پوینت
2. **بازیابی مکالمه** -- فقط پیام‌ها بازگردانی می‌شوند و کد فعلی شما دست‌نخورده می‌ماند
3. **بازیابی کد** -- فقط تغییرات فایل بازگردانده می‌شود و تاریخچه کامل مکالمه حفظ می‌شود
4. **خلاصه‌سازی از اینجا** -- فشرده‌سازی مکالمه از این نقطه به بعد در قالب خلاصه‌ای که هوش مصنوعی تولید می‌کند و آزادسازی فضای پنجره زمینه. پیام‌های پیش از نقطه انتخاب‌شده دست‌نخورده می‌مانند. هیچ فایلی روی دیسک تغییر نمی‌کند. پیام‌های اصلی در رونوشت نشست حفظ می‌شوند. در صورت تمایل می‌توانید دستورهایی بدهید تا خلاصه روی موضوعات مشخصی متمرکز شود.
5. **خلاصه‌سازی تا اینجا** -- همتای رو به عقب: فشرده‌سازی همه چیز *پیش از* نقطه انتخاب‌شده در قالب خلاصه‌ای که هوش مصنوعی تولید می‌کند، با حفظ دست‌نخورده پیام‌های این نقطه به بعد. این گزینه همراه با «خلاصه‌سازی از اینجا» فشرده‌سازی دوسویه و هدفمند پنجره زمینه شما را ممکن می‌کند. هیچ فایلی روی دیسک تغییر نمی‌کند و پیام‌های اصلی در رونوشت نشست حفظ می‌شوند.
6. **بی‌خیال** -- انصراف و بازگشت به وضعیت فعلی

> **توجه**: پس از بازیابی مکالمه یا انتخاب **خلاصه‌سازی از اینجا**، پرامپت اصلی از پیام انتخاب‌شده در فیلد ورودی بازگردانده می‌شود تا بتوانید آن را دوباره ارسال یا ویرایش کنید. انتخاب **خلاصه‌سازی تا اینجا** شما را در انتهای مکالمه با ورودی خالی رها می‌کند.

> **نکته**: پس از یک rewind، پیش از خروج یک پرامپت به Claude بفرستید. Claude Code گفتگوی rewindشده را همراه با همان پرامپت ذخیره می‌کند، پس اگر اول خارج شوید، پیام‌های rewindشده می‌توانند برگردند. برای حذف دوبارهشان، `/rewind` را اجرا کنید، همان پرامپت را انتخاب کنید و **Restore conversation** را بزنید. فایل‌های بازیابی‌شده همان‌طور که rewind رهایشان کرده باقی می‌مانند.

> **`/clear` دیگر یک مرز سخت نیست (v2.1.191+)**: `/rewind` می‌تواند از چک‌پوینتی که *پیش از* اجرای `/clear` گرفته شده است ادامه دهد. پاک کردن مکالمه دیگر وضعیت پیش از آن را برای همیشه دور نمی‌ریزد — اگر به آن کد یا زمینه قبلی نیاز داشته باشید، می‌توانید از آن سوی پاک‌سازی به عقب بازگردید.

## چک‌پوینت‌های خودکار

Claude Code به طور خودکار چک‌پوینت‌ها را برای شما ایجاد می‌کند:

- **با هر پرامپت کاربر** - با هر ورودی کاربر چک‌پوینت جدیدی ایجاد می‌شود
- **پایدار** - چک‌پوینت‌ها همراه مکالمه ذخیره می‌شوند، بنابراین `/rewind` پس از ازسرگیری یک نشست هم کار می‌کند
- **پاک‌سازی خودکار** - چک‌پوینت‌ها پس از ۳۰ روز به طور خودکار پاک می‌شوند

این یعنی همیشه می‌توانید به هر نقطه قبلی مکالمه بازگردید، از چند دقیقه پیش تا چند روز قبل.

## موارد استفاده

| سناریو | گردش‌کار |
|----------|----------|
| **کاوش رویکردها** | ذخیره → امتحان A → ذخیره → بازگردانی → امتحان B → مقایسه |
| **بازآرایی ایمن** | ذخیره → بازآرایی → آزمون → در صورت شکست: بازگردانی |
| **آزمون A/B** | ذخیره → طراحی A → ذخیره → بازگردانی → طراحی B → مقایسه |
| **بازیابی از خطا** | مشاهده مشکل → بازگردانی به آخرین وضعیت سالم |

## استفاده از چک‌پوینت‌ها

### مشاهده و بازگردانی

دو بار `Esc` را فشار دهید یا از `/rewind` استفاده کنید تا مرورگر چک‌پوینت باز شود. فهرستی از همه چک‌پوینت‌های موجود همراه با برچسب زمانی خواهید دید. هر چک‌پوینتی را انتخاب کنید تا به آن وضعیت بازگردید.

### جزئیات چک‌پوینت

هر چک‌پوینت نشان می‌دهد:
- برچسب زمانی لحظه ایجاد آن
- فایل‌هایی که تغییر کرده‌اند
- تعداد پیام‌های مکالمه
- ابزارهایی که استفاده شده‌اند

## مثال‌های عملی

### مثال ۱: کاوش رویکردهای مختلف

```
کاربر: بیایید یک لایه کش به API اضافه کنیم

Claude: کش Redis را به اندپوینت‌های API شما اضافه می‌کنم...
[تغییرات را در چک‌پوینت A اعمال می‌کند]

کاربر: در واقع، بیایید به جای آن کش درون‌حافظه‌ای را امتحان کنیم

Claude: بازگردانی می‌کنم تا رویکرد دیگری را بررسی کنیم...
[کاربر Esc+Esc را فشار می‌دهد و به چک‌پوینت A بازمی‌گردد]
[کش درون‌حافظه‌ای را در چک‌پوینت B پیاده‌سازی می‌کند]

کاربر: حالا می‌توانم هر دو رویکرد را مقایسه کنم
```

### مثال ۲: بازیابی از خطاها

```
کاربر: ماژول احراز هویت را بازآرایی کن تا از JWT استفاده کند

Claude: ماژول احراز هویت را بازآرایی می‌کنم...
[تغییرات گسترده‌ای اعمال می‌کند]

کاربر: صبر کن، این کار یکپارچگی OAuth را خراب کرد. بیایید برگردیم.

Claude: کمک می‌کنم تا به پیش از بازآرایی بازگردید...
[کاربر Esc+Esc را فشار می‌دهد و چک‌پوینت پیش از بازآرایی را انتخاب می‌کند]

کاربر: این بار بیایید رویکرد محافظه‌کارانه‌تری را امتحان کنیم
```

### مثال ۳: آزمایش ایمن

```
کاربر: بیایید این را به سبک تابعی بازنویسی کنیم
[پیش از آزمایش چک‌پوینت ایجاد می‌کند]

Claude: [تغییرات آزمایشی اعمال می‌کند]

کاربر: آزمون‌ها شکست می‌خورند. بیایید بازگردانی کنیم.
[کاربر Esc+Esc را فشار می‌دهد و به چک‌پوینت بازمی‌گردد]

Claude: تغییرات را بازگرداندم. بیایید رویکرد دیگری را امتحان کنیم.
```

### مثال ۴: شاخه‌بندی رویکردها

```
کاربر: می‌خواهم دو طراحی پایگاه داده را مقایسه کنم
[چک‌پوینت را نشانه‌گذاری می‌کند - اسمش را «شروع» می‌گذارد]

Claude: طراحی اول را ایجاد می‌کنم...
[Schema A را پیاده‌سازی می‌کند]

کاربر: حالا بگذار برگردم و رویکرد دوم را امتحان کنم
[کاربر Esc+Esc را فشار می‌دهد و به «شروع» بازمی‌گردد]

Claude: حالا Schema B را پیاده‌سازی می‌کنم...
[Schema B را پیاده‌سازی می‌کند]

کاربر: عالی! حالا هر دو اسکیما را برای انتخاب دارم
```

## نگهداری چک‌پوینت‌ها

Claude Code چک‌پوینت‌های شما را به طور خودکار مدیریت می‌کند:

- چک‌پوینت‌ها با هر پرامپت کاربر به طور خودکار ایجاد می‌شوند
- چک‌پوینت‌های قدیمی تا ۳۰ روز نگه داشته می‌شوند
- چک‌پوینت‌ها به طور خودکار پاک‌سازی می‌شوند تا از رشد نامحدود فضا جلوگیری شود

## الگوهای گردش‌کار

### راهبرد شاخه‌بندی برای کاوش

هنگام کاوش چندین رویکرد:

```
۱. شروع با پیاده‌سازی اولیه → چک‌پوینت A
۲. امتحان رویکرد ۱ → چک‌پوینت B
۳. بازگردانی به چک‌پوینت A
۴. امتحان رویکرد ۲ → چک‌پوینت C
۵. مقایسه نتایج B و C
۶. انتخاب بهترین رویکرد و ادامه
```

### الگوی بازآرایی ایمن

هنگام اعمال تغییرات چشمگیر:

```
۱. وضعیت فعلی → چک‌پوینت (خودکار)
۲. شروع بازآرایی
۳. اجرای آزمون‌ها
۴. اگر آزمون‌ها موفق بودند → ادامه کار
۵. اگر آزمون‌ها شکست خوردند → بازگردانی و امتحان رویکرد دیگر
```

## بهترین شیوه‌ها

چون چک‌پوینت‌ها به طور خودکار ایجاد می‌شوند، می‌توانید روی کار خود تمرکز کنید و نگران ذخیره دستی وضعیت نباشید. با این حال این شیوه‌ها را در نظر داشته باشید:

### استفاده مؤثر از چک‌پوینت‌ها

✅ **بایدها:**
- پیش از بازگردانی، چک‌پوینت‌های موجود را مرور کنید
- وقتی می‌خواهید جهت‌های مختلف را کاوش کنید از بازگردانی استفاده کنید
- چک‌پوینت‌ها را برای مقایسه رویکردهای مختلف نگه دارید
- بدانید هر گزینه بازگردانی چه می‌کند (بازیابی کد و مکالمه، بازیابی مکالمه، بازیابی کد یا خلاصه‌سازی)

❌ **نبایدها:**
- برای حفظ کد فقط به چک‌پوینت‌ها تکیه کنید
- انتظار داشته باشید چک‌پوینت‌ها تغییرات خارجی فایل‌سیستم را ردیابی کنند
- از چک‌پوینت‌ها به جای کامیت‌های git استفاده کنید

## پیکربندی

چک‌پوینت‌ها یک رفتار پیش‌فرض و درونی در Claude Code هستند و برای فعال شدن به هیچ پیکربندی نیاز ندارند. هر پرامپت کاربر به طور خودکار یک چک‌پوینت ایجاد می‌کند.

دو تنظیم رفتار چک‌پوینت را کنترل می‌کنند — اینکه اصلاً عکس‌برداری انجام شود یا نه، و اینکه چه مدت نگه داشته شوند:

```json
{
  "fileCheckpointingEnabled": true,
  "cleanupPeriodDays": 30
}
```

| تنظیم | پیش‌فرض | اثر |
|---------|---------|--------|
| `fileCheckpointingEnabled` | `true` | فایل‌ها را پیش از هر ویرایش عکس‌برداری می‌کند تا `/rewind` بتواند آن‌ها را بازیابی کند. نیازمند v2.1.119+ است. در `/config` به صورت **Rewind code (checkpoints)** نمایش داده می‌شود. معادل متغیر محیطی: `CLAUDE_CODE_DISABLE_FILE_CHECKPOINTING` |
| `cleanupPeriodDays` | `30` | تعداد روزهای نگهداری تاریخچه نشست و چک‌پوینت‌ها |

Claude Code عکس‌ها را برای **۱۰۰ چک‌پوینت آخر** نگه می‌دارد؛ چک‌پوینت‌های قدیمی‌تر حتی در بازه نگهداری هم حذف می‌شوند.

> **به‌روزرسانی v2.1.117**: `cleanupPeriodDays` اکنون ماندگاری بسیاری از کش‌های روی دیسک را کنترل می‌کند، نه فقط چک‌پوینت‌ها (نمونه‌ای در ادامه؛ رونوشت‌های نشست، `file-history/`، `plans/`، `debug/`، `paste-cache/` و موارد بیشتر را هم پوشش می‌دهد):
>
> - چک‌پوینت‌های نشست
> - `~/.claude/tasks/` — فهرست‌های وظیفه پایدار
> - `~/.claude/shell-snapshots/` — عکس‌های ثبت‌شده از محیط پوسته
> - `~/.claude/backups/` — نسخه‌های قبلی `~/.claude.json` (پنج نسخه جدیدتر نگه داشته می‌شوند)
>
> یک تنظیم واحد اکنون این پوشه‌ها را پس از همان تعداد روز به طور یکسان هرس می‌کند.

## محدودیت‌ها

چک‌پوینت‌ها محدودیت‌های زیر را دارند:

- **تغییرات فایلی که فقط با Bash انجام می‌شوند ردیابی نمی‌شوند** - وقتی Claude فایلی را با ابزارهای ویرایش فایل ویرایش کرده باشد، `/rewind` تغییراتی را هم که فرمان‌های Bash بعد از آن روی همان فایل می‌سازند خنثی می‌کند؛ فایلی که فقط فرمان‌های Bash تغییرش داده‌اند ردیابی نمی‌شود. از v2.1.309، `sed -i` مثل هر ویرایش Bash دیگری رفتار می‌شود
- **تغییرات خارجی ردیابی نمی‌شوند** - تغییراتی که بیرون از Claude Code (در ویرایشگر، ترمینال و غیره) انجام می‌شوند ثبت نمی‌شوند
- **جایگزین کنترل نسخه نیست** - برای تغییرات دائمی و قابل حسابرسی در کدبیس از git استفاده کنید
- **ویرایش‌های زیرایجنت بازیابی نمی‌شوند** - ویرایش‌های یک زیرایجنت روی فایل‌هایی که Claude پیش‌تر در گفتگوی شما ویرایششان نکرده ردیابی نمی‌شوند، بنابراین `/rewind` آن‌ها را همان‌طور که هستند رها می‌کند (با git بازشان گردانید)؛ استثنا مهارت `context: fork` در پیش‌زمینه است که ویرایش‌هایش مانند نشست اصلی بازیابی می‌شود

> **به‌روزرسانی v2.1.216**: `/rewind` دیگر فایل‌ها را از طریق پیوند نمادین یا پیوند سخت در مسیرهای ردیابی‌شده بازیابی یا حذف نمی‌کند. اگر یک مسیر ردیابی‌شده از طریق پیوند نمادین یا سخت حل شود، بازگردانی به جای دنبال کردن پیوند از آن می‌گذرد و گزارش می‌کند که چند مسیر را به این دلیل نادیده گرفته است.

- بررسی کنید آیا چک‌پوینت‌ها پاک شده‌اند
- فضای دیسک را بررسی کنید
- مطمئن شوید `cleanupPeriodDays` به اندازه کافی بالا تنظیم شده است (پیش‌فرض: ۳۰ روز)

### شکست در بازگردانی

**مشکل**: نمی‌توان به چک‌پوینت بازگردید

**راه‌حل**:
- مطمئن شوید تغییرات ذخیره‌نشده‌ای با بازگردانی تعارض ندارد
- بررسی کنید آیا چک‌پوینت خراب شده است
- بازگردانی به چک‌پوینت دیگری را امتحان کنید

## یکپارچگی با Git

چک‌پوینت‌ها مکمل git هستند (نه جایگزین آن):

| ویژگی | Git | چک‌پوینت‌ها |
|---------|-----|-------------|
| دامنه | فایل‌سیستم | مکالمه + فایل‌ها |
| ماندگاری | دائمی | مبتنی بر نشست |
| دانه‌بندی | کامیت‌ها | هر نقطه |
| سرعت | کندتر | لحظه‌ای |
| اشتراک‌گذاری | بله | محدود |

از هر دو با هم استفاده کنید:
1. از چک‌پوینت‌ها برای آزمایش سریع استفاده کنید
2. برای تغییرات نهایی از کامیت‌های git استفاده کنید
3. پیش از عملیات git چک‌پوینت ایجاد کنید
4. وضعیت‌های موفق چک‌پوینت را در git کامیت کنید

## راهنمای شروع سریع

### گردش‌کار پایه

1. **به طور عادی کار کنید** - Claude Code چک‌پوینت‌ها را به طور خودکار ایجاد می‌کند
2. **می‌خواهید برگردید؟** - دو بار `Esc` را فشار دهید یا از `/rewind` استفاده کنید
3. **چک‌پوینت را انتخاب کنید** - از فهرست انتخاب کنید تا بازگردانی انجام شود
4. **انتخاب کنید چه چیزی بازیابی شود** - از میان بازیابی کد و مکالمه، بازیابی مکالمه، بازیابی کد، خلاصه‌سازی از اینجا، خلاصه‌سازی تا اینجا یا انصراف یکی را برگزینید
5. **به کار ادامه دهید** - به آن نقطه بازگشته‌اید

### میان‌برهای صفحه‌کلید

- **`Esc` + `Esc`** - باز کردن مرورگر چک‌پوینت
- **`/rewind`** - راهی جایگزین برای دسترسی به چک‌پوینت‌ها
- **`/checkpoint`**، **`/undo`** - نام‌های مستعار `/rewind`

## دانستن زمان بازگردانی: پایش زمینه

چک‌پوینت‌ها به شما امکان بازگشت می‌دهند — اما از کجا می‌دانید *چه زمانی* باید برگردید؟ با رشد مکالمه، پنجره زمینه Claude پر می‌شود و کیفیت مدل بی‌سروصدا افت می‌کند. ممکن است بدون آنکه متوجه باشید، کدی را از مدلی نیمه‌کور تحویل دهید.

**[cc-زمینه-stats](https://github.com/luongnv89/cc-زمینه-stats)** این مشکل را با افزودن **مناطق زمینه** به‌صورت زمان‌واقعی به نوار وضعیت Claude Code حل می‌کند. این ابزار نشان می‌دهد در پنجره زمینه کجا هستید — از **Plan** (سبز، ایمن برای برنامه‌ریزی و کدنویسی) تا **Code** (زرد، از شروع برنامه‌های جدید بپرهیزید) تا **Dump** (نارنجی، کار را تمام کنید و بازگردانی کنید). وقتی جابه‌جایی منطقه را دیدید، می‌دانید وقت آن است چک‌پوینت بگیرید و از نو شروع کنید، نه اینکه با خروجی افت‌کرده ادامه دهید.

## خلاصه

چک‌پوینت‌ها ویژگی خودکار Claude Code هستند که به شما امکان می‌دهند بدون ترس از دست دادن کار، رویکردهای مختلف را با خیال راحت کاوش کنید. هر پرامپت کاربر به طور خودکار چک‌پوینت جدیدی ایجاد می‌کند، بنابراین می‌توانید به هر نقطه قبلی نشست خود بازگردید.

مزایای کلیدی:
- آزمایش بی‌باکانه چندین رویکرد
- بازیابی سریع از خطاها
- مقایسه راه‌حل‌های مختلف در کنار هم
- یکپارچگی ایمن با سیستم‌های کنترل نسخه

به یاد داشته باشید: چک‌پوینت‌ها جایگزین git نیستند. از چک‌پوینت‌ها برای آزمایش سریع و از git برای تغییرات دائمی کد استفاده کنید.
