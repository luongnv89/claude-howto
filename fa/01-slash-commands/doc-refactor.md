# بازسازی مستندات

ساختار مستندات پروژه را متناسب با نوع پروژه بازسازی کنید:

1. **تحلیل پروژه**: شناسایی نوع (کتابخانه/API/برنامه وب/CLI/microservices)، معماری و personas کاربر
2. **مرکزسازی مستندات**: انتقال مستندات فنی به `docs/` با ارجاعات متقابل مناسب
3. **README.md ریشه**: ساده‌سازی به‌عنوان نقطه ورودی با مرور کلی، quickstart، خلاصه ماژول‌ها/اجزا، لایسنس، مخاطبان
4. **مستندات اجزا**: افزودن فایل‌های README در سطح ماژول/بسته/سرویس با دستورالعمل راه‌اندازی و تست
5. **سازماندهی `docs/`** بر اساس دسته‌های مرتبط:
   - معماری، مرجع API، پایگاه‌داده، طراحی، رفع اشکال، استقرار، مشارکت (تطبیق با نیازهای پروژه)
6. **ایجاد راهنماها** (انتخاب موارد قابل اجرا):
   - راهنمای کاربر: مستندات کاربر نهایی برای برنامه‌ها
   - مستندات API: endpointها، احراز هویت، مثال‌ها برای APIها
   - راهنمای توسعه: راه‌اندازی، تست، گردش کار مشارکت
   - راهنمای استقرار: استقرار تولید برای سرویس‌ها/برنامه‌ها
7. **استفاده از Mermaid** برای همه نمودارها (معماری، جریان‌ها، schemaها)

مستندات را مختصر، قابل پیمایش و مرتبط با نوع پروژه نگه دارید.
