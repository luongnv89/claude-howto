# 🔄 自动化工作流程

**核心原则：**

- **先探索：** 始终从自动探索代码库收集产品信息开始，不要一开始就询问产品相关问题。
- **规划前先询问：** 探索完成后，向用户展示发现的信息，并在制定计划**之前**询问视频偏好（尺寸、风格、时长、自定义需求）。
- **产品 URL 优先：** 当找到或提供产品 URL 时，它将作为**主要信息来源**，产品页面上的信息优先于代码库发现的内容。
- **价值高于技术：** 聚焦于价值主张、客户利益和功能特性（用户能获得什么），而非技术规格或实现细节。
- **以客户为中心：** 强调产品如何解决问题、改善生活或为用户带来价值。
- **自主执行：** 用户确认偏好后，自主完成规划和实施，无需进一步获取审批。

## 📋 第一阶段：自主资源发现

**目标：** 自动探索代码库并收集所有可用的产品信息，无需向用户提问。

**操作步骤：**

1. **自动优先探索代码库：**
   - 在 `README.md` 中搜索产品描述和价值主张
   - 检查 `package.json` 获取产品名称、描述、主页 URL
   - 在 `/assets`、`/public`、`/static`、`/images` 目录中查找品牌资源
   - 从 CSS/Tailwind 配置文件中提取配色方案
   - 查找现有的营销文案或文档
   - 在配置文件、环境变量或文档中查找产品 URL

2. **如果找到产品 URL，立即获取：**
   - 使用 WebFetch 从产品页面提取信息
   - 产品页面信息优先于代码库发现的内容
   - 提取所有价值主张、功能特性和品牌信息

3. **综合所有收集到的信息：**
   - 产品名称和描述
   - 价值主张
   - 核心功能和优势
   - 品牌颜色和风格
   - 目标受众（从语气推断）
   - 现有资源或媒体

4. **对缺失信息应用智能默认值：**
   - **视频格式：** 横屏 1920x1080（YouTube/网页优化）
   - **时长：** 30 秒（适合大多数平台）
   - **风格：** 现代、简洁、专业（基于品牌）
   - **品牌颜色：** 使用提取的颜色或互补的现代调色板

5. **仅在以下情况下询问用户（探索后）：**
   - 无法确定产品名称或找到任何产品信息
   - 无法找到或访问产品 URL
   - 存在关键歧义（例如 B2B 与 B2C 会显著改变信息传递方式）
   - 存在需要澄清的相互矛盾的信息

**重要提示：** 完整、静默、自主地完成整个探索过程。不要询问"我需要哪些信息才能开始"或列出要求。只有在真正必要时才打断用户。

**输出：** 携带所有收集到的信息，立即进入第二阶段。

## 🔍 第二阶段：信息分析与深入研究

**目标：** 分析收集到的信息，提取视频创作的关键洞察。

**操作步骤：**

1. **审查第一阶段收集的所有信息：**
   - 产品页面内容（如果找到并获取了 URL）
   - 代码库发现（README、package.json、资源等）
   - 任何品牌指南或营销材料

2. **提取并优先排序（聚焦价值，而非技术）：**
   - **价值主张**（首要关注点）— 对客户的核心利益
   - **客户收益**（用户获得什么）— 如何改善他们的生活
   - **核心功能**（以利益描述，而非技术规格）
   - **独特卖点** — 是什么让它与众不同/更好
   - **使用场景** — 现实世界中的应用
   - **品牌标识**（颜色、字体、风格、语调）
   - **目标受众洞察**（面向哪些人群）
   - **情感诉求**与信息传递（人们为什么关心）

3. **用智能推断静默填补空白：**
   - 如果价值主张不明确，从功能特性和目标受众推断
   - 如果目标受众不明确，从产品类型和信息语调推断
   - 如果缺少品牌颜色，创建互补的现代调色板
   - 避免技术实现细节，除非面向用户

4. **仅在以下情况下请求澄清：**
   - 存在多个相互矛盾的价值主张
   - 无法判断产品是 B2B 还是 B2C（严重影响信息传递）
   - 目标受众真正模糊

**输出：** 清晰理解产品价值、利益和品牌，为视频创作做好准备。

   ```text
   目标受众：[面向哪些人群]
   ```

2. **询问用户偏好（继续前必须完成）：**

   使用清晰、简洁的格式：

   ```text

   1. **视频尺寸/格式：**

      - 竖屏 (1080x1920) - TikTok、Instagram Reels

   2. **视频时长：**
   ```

4. **确认偏好并总结：**
   - 总结用户的选择
   - 应用任何自定义需求
   - 以确认的方向进入结构设计阶段

**输出：** 用户确认的视频规格，为规划阶段做好准备。

## 💻 第六阶段：实施

**目标：** 自主构建完整的 Remotion 视频项目。

**约束与技术栈：**

1. **框架：** Remotion（React）
2. **样式：** Tailwind CSS（通过 `className` 或标准 style 对象）
3. **动画：** 使用 `spring`、`interpolate` 和 `useCurrentFrame` 实现流畅动效
4. **代码风格：** 模块化组件，不要把所有内容堆到 `Root.tsx` 中
5. **最佳实践：**
   - 没有任何东西应该是静态的。所有元素必须有入场（opacity/scale/slide）和退场动画
   - 如需图标，使用 Lucide-React
   - 使用标准字体但进行大胆的样式设计（粗体、字距收紧）
   - 不使用外部图片，除非是占位符（例如 `https://placehold.co/600x400`）或用户提供的资源

**操作步骤：**

1. **按照以下顺序构建完整项目结构：**
   - 工具函数（缓动函数、动画辅助工具、颜色工具）
   - 可复用组件（AnimatedTitle、FeatureHighlight、转场效果）
   - 场景组件（HookScene、DemoScene、CTAScene）
   - 主合成（Video.tsx 包含序列编排）
   - Root 配置（Root.tsx 包含正确注册）

2. **静默高效地工作：**
   - 创建所有文件，不需要逐步解说每个步骤
   - 根据收集到的信息做出设计决策
   - 运用专业动画原理
   - 确保场景间的流畅过渡

3. **实施完成后自动进入第七阶段。**

**输出：** 完整的、可投入生产的 Remotion 项目代码。

**创意质量：**
- 清晰的叙事结构
- 引人入胜的开场

- 令人难忘的视觉时刻
