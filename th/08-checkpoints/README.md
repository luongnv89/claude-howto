# Checkpoints และการย้อนกลับ (Rewind)

Checkpoints ช่วยให้คุณบันทึกสถานะของการสนทนาและย้อนกลับไปยังจุดก่อนหน้าในเซสชัน Claude Code ได้ ฟีเจอร์นี้มีคุณค่าอย่างยิ่งสำหรับการสำรวจแนวทางต่างๆ การกู้คืนจากข้อผิดพลาด หรือการเปรียบเทียบแนวทางแก้ปัญหาทางเลือก

## ภาพรวม

Checkpoints ช่วยให้คุณบันทึกสถานะการสนทนาและย้อนกลับไปยังจุดก่อนหน้า ทำให้สามารถทดลองและสำรวจแนวทางหลายรูปแบบได้อย่างปลอดภัย Checkpoint คือภาพถ่ายสถานะการสนทนาของคุณ ซึ่งประกอบด้วย:
- ข้อความทั้งหมดที่แลกเปลี่ยนกัน
- การแก้ไขไฟล์ที่ดำเนินการ
- ประวัติการใช้เครื่องมือ
- บริบทของเซสชัน

Checkpoints มีประโยชน์อย่างยิ่งเมื่อต้องการสำรวจแนวทางที่แตกต่าง กู้คืนจากข้อผิดพลาด หรือเปรียบเทียบแนวทางแก้ปัญหาทางเลือก

## แนวคิดหลัก

| แนวคิด | คำอธิบาย |
|---------|-------------|
| **Checkpoint** | ภาพถ่ายสถานะการสนทนา รวมถึงข้อความ ไฟล์ และบริบท |
| **Rewind** | กลับไปยัง checkpoint ก่อนหน้า โดยละทิ้งการเปลี่ยนแปลงที่เกิดขึ้นหลังจากนั้น |
| **Branch Point** | Checkpoint ที่ใช้เป็นจุดเริ่มต้นสำหรับสำรวจหลายแนวทาง |

## การเข้าถึง Checkpoints

คุณสามารถเข้าถึงและจัดการ checkpoints ได้สองวิธีหลัก:

### ใช้แป้นพิมพ์ลัด
กด `Esc` สองครั้ง (`Esc` + `Esc`) เพื่อเปิดอินเทอร์เฟซ checkpoint และเรียกดู checkpoints ที่บันทึกไว้

### ใช้ slash command
ใช้คำสั่ง `/rewind` (หรือชื่อแทน `/checkpoint`) เพื่อเข้าถึงอย่างรวดเร็ว:

```bash
# เปิดอินเทอร์เฟซ rewind
/rewind

# หรือใช้ชื่อแทน
/checkpoint
```

## ตัวเลือกของ Rewind

เมื่อคุณเลือก rewind ระบบจะแสดงเมนูห้าตัวเลือก:

1. **Restore code and conversation** — ย้อนกลับทั้งไฟล์และข้อความไปยัง checkpoint นั้น
2. **Restore conversation** — ย้อนกลับเฉพาะข้อความ คงโค้ดปัจจุบันไว้
3. **Restore code** — ย้อนกลับเฉพาะการเปลี่ยนแปลงไฟล์ คงประวัติการสนทนาทั้งหมดไว้
4. **Summarize from here** — บีบอัดการสนทนาจากจุดนี้เป็นต้นไปเป็นสรุปที่สร้างโดย AI เพื่อประหยัดพื้นที่ context window ข้อความก่อนจุดที่เลือกจะคงอยู่ ไม่มีการเปลี่ยนแปลงไฟล์ในดิสก์ ข้อความต้นฉบับยังคงอยู่ใน session transcript คุณสามารถระบุคำสั่งเพิ่มเติมเพื่อให้สรุปเน้นหัวข้อเฉพาะได้
5. **Never mind** — ยกเลิกและกลับสู่สถานะปัจจุบัน

> **หมายเหตุ**: หลังจากกู้คืนการสนทนาหรือสร้างสรุป ระบบจะนำ prompt ต้นฉบับจากข้อความที่เลือกกลับมาในช่องป้อนข้อมูล เพื่อให้คุณสามารถส่งซ้ำหรือแก้ไขได้

## Checkpoints อัตโนมัติ

Claude Code สร้าง checkpoints ให้คุณโดยอัตโนมัติ:

- **ทุก prompt ของผู้ใช้** — checkpoint ใหม่ถูกสร้างพร้อมกับการป้อนข้อมูลของผู้ใช้แต่ละครั้ง
- **คงอยู่ถาวร** — Checkpoints คงอยู่ข้ามเซสชัน
- **ล้างอัตโนมัติ** — Checkpoints ถูกล้างโดยอัตโนมัติหลังจาก 30 วัน

ซึ่งหมายความว่าคุณสามารถย้อนกลับไปยังจุดใดก็ได้ในการสนทนา ตั้งแต่เมื่อสองสามนาทีก่อนจนถึงหลายวันก่อน

## กรณีการใช้งาน

| สถานการณ์ | ขั้นตอนการทำงาน |
|----------|----------|
| **สำรวจแนวทาง** | บันทึก → ลองแนวทาง A → บันทึก → Rewind → ลองแนวทาง B → เปรียบเทียบ |
| **การ Refactor อย่างปลอดภัย** | บันทึก → Refactor → ทดสอบ → หากล้มเหลว: Rewind |
| **ทดสอบ A/B** | บันทึก → ออกแบบ A → บันทึก → Rewind → ออกแบบ B → เปรียบเทียบ |
| **กู้คืนจากข้อผิดพลาด** | พบปัญหา → Rewind ไปยังสถานะที่ดีล่าสุด |

## การใช้งาน Checkpoints

### การดูและการ Rewind

กด `Esc` สองครั้งหรือใช้ `/rewind` เพื่อเปิด checkpoint browser คุณจะเห็นรายการ checkpoints ทั้งหมดพร้อมเวลาประทับ เลือก checkpoint ใดก็ได้เพื่อ rewind ไปยังสถานะนั้น

### รายละเอียด Checkpoint

แต่ละ checkpoint แสดง:
- เวลาประทับของการสร้าง
- ไฟล์ที่ถูกแก้ไข
- จำนวนข้อความในการสนทนา
- เครื่องมือที่ถูกใช้

## การเก็บรักษา Checkpoint

Claude Code จัดการ checkpoints ของคุณโดยอัตโนมัติ:

- Checkpoints ถูกสร้างโดยอัตโนมัติพร้อมกับ prompt ของผู้ใช้ทุกครั้ง
- Checkpoints เก่าจะถูกเก็บไว้นานสูงสุด 30 วัน
- Checkpoints จะถูกล้างโดยอัตโนมัติเพื่อป้องกันการใช้พื้นที่เก็บข้อมูลโดยไม่จำกัด

## รูปแบบการทำงาน (Workflow Patterns)

### กลยุทธ์การแยกสาขาสำหรับการสำรวจ

เมื่อสำรวจหลายแนวทาง:

```
1. เริ่มต้นด้วยการใช้งานเบื้องต้น → Checkpoint A
2. ลองแนวทาง 1 → Checkpoint B
3. Rewind ไปยัง Checkpoint A
4. ลองแนวทาง 2 → Checkpoint C
5. เปรียบเทียบผลลัพธ์จาก B และ C
6. เลือกแนวทางที่ดีที่สุดและดำเนินการต่อ
```

### รูปแบบการ Refactor อย่างปลอดภัย

เมื่อทำการเปลี่ยนแปลงครั้งใหญ่:

```
1. สถานะปัจจุบัน → Checkpoint (อัตโนมัติ)
2. เริ่มการ refactor
3. รันการทดสอบ
4. หากการทดสอบผ่าน → ทำงานต่อ
5. หากการทดสอบล้มเหลว → Rewind และลองแนวทางอื่น
```

## แนวปฏิบัติที่ดี

เนื่องจาก checkpoints ถูกสร้างโดยอัตโนมัติ คุณสามารถมุ่งความสนใจไปที่งานโดยไม่ต้องกังวลเรื่องการบันทึกสถานะด้วยตนเอง อย่างไรก็ตาม ควรคำนึงถึงแนวปฏิบัติเหล่านี้:

### การใช้ Checkpoints อย่างมีประสิทธิภาพ

✅ **ควรทำ:**
- ตรวจสอบ checkpoints ที่มีอยู่ก่อน rewind
- ใช้ rewind เมื่อต้องการสำรวจทิศทางที่แตกต่าง
- เก็บ checkpoints ไว้เพื่อเปรียบเทียบแนวทางต่างๆ
- ทำความเข้าใจตัวเลือกแต่ละอย่างของ rewind (กู้คืนโค้ดและการสนทนา, กู้คืนการสนทนา, กู้คืนโค้ด, หรือสรุป)

❌ **ไม่ควรทำ:**
- พึ่งพา checkpoints เพียงอย่างเดียวสำหรับการเก็บรักษาโค้ด
- คาดหวังให้ checkpoints ติดตามการเปลี่ยนแปลงไฟล์ภายนอก
- ใช้ checkpoints แทน git commits

## การกำหนดค่า

Checkpoints เป็นพฤติกรรมเริ่มต้นของ Claude Code และไม่ต้องมีการกำหนดค่าใดๆ เพื่อเปิดใช้งาน ทุก prompt ของผู้ใช้จะสร้าง checkpoint โดยอัตโนมัติ

การตั้งค่าที่เกี่ยวข้องกับ checkpoint เพียงอย่างเดียวคือ `cleanupPeriodDays` ซึ่งควบคุมระยะเวลาที่เซสชันและ checkpoints ถูกเก็บไว้:

```json
{
  "cleanupPeriodDays": 30
}
```

- `cleanupPeriodDays`: จำนวนวันที่เก็บประวัติเซสชันและ checkpoints ไว้ (ค่าเริ่มต้น: `30`)

> **การอัปเดต v2.1.117**: `cleanupPeriodDays` ปัจจุบันควบคุมการเก็บรักษาสำหรับแคชในดิสก์สี่รายการ ไม่ใช่แค่ checkpoints:
>
> - Session checkpoints
> - `~/.claude/tasks/` — รายการงานถาวร
> - `~/.claude/shell-snapshots/` — ภาพถ่าย shell-environment ที่บันทึกไว้
> - `~/.claude/backups/` — การสำรองข้อมูลการตั้งค่า / CLAUDE.md แบบหมุนเวียน
>
> การตั้งค่าเดียวจะตัดแต่งไดเรกทอรีทั้งสี่อย่างสม่ำเสมอหลังจากจำนวนวันเดียวกัน

## ข้อจำกัด

Checkpoints มีข้อจำกัดดังนี้:

- **คำสั่ง Bash ไม่ถูกติดตาม** — การดำเนินการเช่น `rm`, `mv`, `cp` บนไฟล์ระบบไม่ถูกบันทึกใน checkpoints
- **การเปลี่ยนแปลงภายนอกไม่ถูกติดตาม** — การเปลี่ยนแปลงที่เกิดขึ้นภายนอก Claude Code (ใน editor หรือ terminal) ไม่ถูกบันทึก
- **ไม่ใช่ตัวแทน version control** — ใช้ git สำหรับการเปลี่ยนแปลงถาวรและตรวจสอบได้ในโค้ดเบสของคุณ

## การแก้ไขปัญหา

### Checkpoint หายไป

**ปัญหา**: ไม่พบ checkpoint ที่คาดหวัง

**วิธีแก้ไข**:
- ตรวจสอบว่า checkpoints ถูกล้างหรือไม่
- ตรวจสอบพื้นที่ว่างในดิสก์
- ตรวจสอบว่า `cleanupPeriodDays` ตั้งค่าสูงพอ (ค่าเริ่มต้น: 30 วัน)

### Rewind ล้มเหลว

**ปัญหา**: ไม่สามารถ rewind ไปยัง checkpoint

**วิธีแก้ไข**:
- ตรวจสอบว่าไม่มีการเปลี่ยนแปลงที่ยังไม่ commit ที่ขัดแย้ง
- ตรวจสอบว่า checkpoint ไม่เสียหาย
- ลอง rewind ไปยัง checkpoint อื่น

## การผสานรวมกับ Git

Checkpoints เสริม (แต่ไม่แทนที่) git:

| ฟีเจอร์ | Git | Checkpoints |
|---------|-----|-------------|
| ขอบเขต | ไฟล์ระบบ | การสนทนา + ไฟล์ |
| ความถาวร | ถาวร | ตามเซสชัน |
| ความละเอียด | Commits | จุดใดก็ได้ |
| ความเร็ว | ช้ากว่า | ทันที |
| การแชร์ | ใช่ | จำกัด |

ใช้ทั้งสองร่วมกัน:
1. ใช้ checkpoints สำหรับการทดลองอย่างรวดเร็ว
2. ใช้ git commits สำหรับการเปลี่ยนแปลงที่สรุปแล้ว
3. สร้าง checkpoint ก่อนดำเนินการ git
4. Commit สถานะ checkpoint ที่สำเร็จไปยัง git

## คู่มือเริ่มต้นอย่างรวดเร็ว

### ขั้นตอนพื้นฐาน

1. **ทำงานตามปกติ** — Claude Code สร้าง checkpoints โดยอัตโนมัติ
2. **ต้องการย้อนกลับ?** — กด `Esc` สองครั้งหรือใช้ `/rewind`
3. **เลือก checkpoint** — เลือกจากรายการเพื่อ rewind
4. **เลือกสิ่งที่จะกู้คืน** — เลือกจาก กู้คืนโค้ดและการสนทนา, กู้คืนการสนทนา, กู้คืนโค้ด, สรุปจากจุดนี้ หรือยกเลิก
5. **ทำงานต่อ** — คุณกลับมาอยู่ที่จุดนั้นแล้ว

### แป้นพิมพ์ลัด

- **`Esc` + `Esc`** — เปิด checkpoint browser
- **`/rewind`** — วิธีเข้าถึง checkpoints แบบอื่น
- **`/checkpoint`** — ชื่อแทนสำหรับ `/rewind`

## การรู้ว่าเมื่อใดควร Rewind: การติดตาม Context

Checkpoints ช่วยให้คุณย้อนกลับได้ แต่คุณจะรู้ได้อย่างไรว่า *เมื่อใด* ควรทำ? เมื่อการสนทนาขยายตัว context window ของ Claude จะเต็มขึ้นและคุณภาพของโมเดลจะลดลงอย่างเงียบๆ คุณอาจกำลังส่งโค้ดจากโมเดลที่มองเห็นเพียงครึ่งเดียวโดยไม่รู้ตัว

**[cc-context-stats](https://github.com/luongnv89/cc-context-stats)** แก้ปัญหานี้โดยเพิ่ม **context zones** แบบเรียลไทม์ในแถบสถานะ Claude Code ของคุณ โดยติดตามว่าคุณอยู่ที่จุดใดใน context window — ตั้งแต่ **Plan** (สีเขียว ปลอดภัยสำหรับการวางแผนและเขียนโค้ด) ผ่าน **Code** (สีเหลือง หลีกเลี่ยงการเริ่มแผนใหม่) ไปจนถึง **Dump** (สีส้ม ให้จบงานและ rewind) เมื่อคุณเห็น zone เปลี่ยน คุณจะรู้ว่าถึงเวลาสร้าง checkpoint และเริ่มใหม่แทนที่จะดำเนินต่อด้วยผลลัพธ์ที่ลดลง

## สรุป

Checkpoints เป็นฟีเจอร์อัตโนมัติใน Claude Code ที่ช่วยให้คุณสำรวจแนวทางต่างๆ ได้อย่างปลอดภัยโดยไม่ต้องกังวลว่างานจะสูญหาย ทุก prompt ของผู้ใช้จะสร้าง checkpoint ใหม่โดยอัตโนมัติ ดังนั้นคุณสามารถย้อนกลับไปยังจุดใดก็ได้ในเซสชันของคุณ

ประโยชน์หลัก:
- ทดลองกับหลายแนวทางได้อย่างกล้าหาญ
- กู้คืนจากข้อผิดพลาดได้อย่างรวดเร็ว
- เปรียบเทียบแนวทางแก้ปัญหาต่างๆ แบบเคียงกัน
- ผสานรวมกับระบบ version control ได้อย่างปลอดภัย

จำไว้ว่า checkpoints ไม่ใช่ตัวแทน git ใช้ checkpoints สำหรับการทดลองอย่างรวดเร็ว และใช้ git สำหรับการเปลี่ยนแปลงโค้ดถาวร
