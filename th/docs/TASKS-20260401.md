## Phase 1 — Infrastructure และโมดูลที่อ่อนแอ (เมษายน 2026)

**Milestone เป้าหมาย: M1**

### เสาหลัก 4: Newcomer Onboarding

- [ ] **T-001** — เขียน `scripts/quickstart.sh`
  - ตรวจหาไดเรกทอรี `~/.claude/` (สร้างพร้อมการยืนยันจากผู้ใช้หากไม่มี)
  - คัดลอก slash command แรก + CLAUDE.md + skill ไปยังการตั้งค่าของผู้ใช้
  - เพิ่มบรรทัด agent-discovery ใน CLAUDE.md เชื่อมโยงไปยัง AGENT-INDEX.md
  - Idempotent: ข้ามไฟล์ที่มีอยู่แล้วพร้อมคำเตือน ไม่เขียนทับ
  - แสดงขั้นตอนถัดไปเมื่อทำงานเสร็จ

- [ ] **T-002** — สร้าง `QUICKSTART.md` (คู่มือ visual สำหรับ 15 นาทีแรก)
  - ขั้นตอน terminal พร้อมคำอธิบายเป็น code block (หลีกเลี่ยงภาพหน้าจอ PNG เท่าที่ทำได้; เลือกใช้ ASCII หรือ Mermaid)
  - บันทึกว่าคำสั่งใดสร้าง visual แต่ละส่วนเพื่อให้สามารถ re-capture ได้

- [ ] **T-003** — เพิ่ม difficulty badge ให้ README ของทั้ง 10 โมดูล
  - รูปแบบ: `> 🟢 **Beginner** | ⏱ 30 minutes` ที่ด้านบนของ README แต่ละโมดูล
  - เพิ่มตัวอย่าง "What you'll build" แบบ bullet ใต้ badge

### เสาหลัก 7: Living Curriculum

- [ ] **T-004** — สร้าง `WHATS-NEW.md`
  - รูปแบบ: `## CC vX.X — DATE` พร้อม bullet item ต่อการเปลี่ยนแปลงฟีเจอร์
  - เพิ่มอย่างน้อยหนึ่งรายการสำหรับ CC version ปัจจุบัน

- [ ] **T-005** — เพิ่ม version badge ให้ README ของทั้ง 10 โมดูล
  - รูปแบบ: `> ✅ Verified against Claude Code **vX.X.X** · Last verified: YYYY-MM-DD`
  - เพิ่ม `cc_version_verified` ใน frontmatter ของแต่ละโมดูล

- [ ] **T-006** — สร้าง `.github/workflows/staleness-check.yml`
  - กำหนดการ: ทุกวันจันทร์ 09:00 UTC
  - อ่านวันที่ `last_verified` ของแต่ละโมดูลจาก frontmatter (ใช้ `yq` หรือ Python script 10 บรรทัด)
  - สร้าง GitHub Issue สำหรับโมดูลที่ไม่ได้รับการยืนยันมากกว่า 30 วัน
  - ข้ามหากมี issue ที่เปิดอยู่ด้วยชื่อเดียวกันอยู่แล้ว

### เสาหลัก 6: Content Quality (CLAUDE.md)

- [ ] **T-007** — สร้าง root `CLAUDE.md` สำหรับโปรเจกต์
  - แสดงแนวปฏิบัติที่ดีผ่านการกำหนดค่าของโปรเจกต์เอง
  - บันทึกแนวทางการ contribute, โครงสร้างโมดูล, และ workflow การบำรุงรักษา

### เสาหลัก 2: AI Agent Index (Generator)

- [ ] **T-008** — เขียน `scripts/build-agent-index.py`
  - อ่านไฟล์ README ของทั้ง 10 โมดูล
  - สกัด: heading (→ topic), code block (→ ตัวอย่างพร้อม language tag), ตาราง (→ ข้อมูลอ้างอิง)
  - ส่งออก `agent-manifest.json` ด้วย schema ที่กำหนดไว้ในแผน CEO
  - ส่งออก `AGENT-INDEX.md` (สรุปที่มนุษย์อ่านได้)
  - ตรวจสอบว่า reference ชี้ไปยังไฟล์ที่มีอยู่จริง

### โมดูล 08-checkpoints: การปรับปรุงเชิงลึกเต็มรูปแบบ (311 → 800+ บรรทัด)

- [ ] **T-010** — เพิ่ม decision tree สำหรับกลยุทธ์ checkpoint (Mermaid flowchart)

- [ ] **T-011** — เพิ่ม workflow template 3 แบบ
  - workflow การ refactoring อย่างปลอดภัย

  - workflow การกู้คืนจากภัยพิบัติ

- [ ] **T-012** — เพิ่มส่วนการทำงานร่วมกับ planning mode

### โมดูล 06-hooks: การปรับปรุงเชิงลึกเต็มรูปแบบ

- [ ] **T-016** — เขียนบทนำโมดูลใหม่ด้วย scenario จากสถานการณ์จริง
  - ตัวอย่าง: "CI ของคุณจับ lint error ได้หลังจาก 20 นาที Hooks จับได้ใน 2 วินาที..."

- [ ] **T-017** — เพิ่ม decision tree สำหรับ hooks (Mermaid flowchart)
  - "ฉันต้องการ trigger X เมื่อ Y เกิดขึ้น" → ตามลูกศร → มาถึงประเภทของ hook

- [ ] **T-018** — เพิ่มตัวอย่าง hook ครบชุด 5 รายการพร้อม script เต็ม (~80 บรรทัดต่อรายการ)
  1. Auto-format เมื่อเขียนไฟล์ (prettier/black)
  2. Security scan เมื่อ commit (trufflehog/bandit)
  3. Test runner เมื่อไฟล์เปลี่ยนแปลง
  4. การแจ้งเตือนเมื่อ session สิ้นสุด
  5. การตรวจสอบ prompt (บล็อก pattern ที่อันตราย)

- [ ] **T-019** — เพิ่มบล็อก "Try It Now" 2 รายการขึ้นไปพร้อมคำสั่งที่ตรวจสอบได้

- [ ] **T-020** — เพิ่มส่วน "Patterns & Recipes" พร้อม named pattern 2 รายการขึ้นไป
