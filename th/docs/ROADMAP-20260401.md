# แผนพัฒนา: claude-howto 2026–2027

> เมษายน 2026 – มีนาคม 2027 · ระบบฐานความรู้สองชั้น | แผนฉบับเต็ม: `TASKS-20260401.md`

---

## วิสัยทัศน์

แปลง claude-howto จาก repository บทเรียนแบบ static ให้กลายเป็น **ระบบความรู้ที่มีชีวิตสำหรับสองกลุ่มผู้ใช้**:

- **สำหรับมนุษย์** — การเรียนรู้เชิงโต้ตอบแบบ scenario-based พร้อมระดับความยากที่เพิ่มขึ้นตามลำดับ, decision tree, และ pattern ที่ผู้เชี่ยวชาญใช้อ้างอิง
- **สำหรับ AI agent** — ดัชนี metadata ที่มีโครงสร้าง ซึ่ง agent สามารถ query ก่อนดำเนินงาน Claude Code ทำให้ repository นี้เป็นโครงสร้างพื้นฐาน ไม่ใช่แค่เนื้อหา

ยังไม่มีคู่แข่งรายใดที่มุ่งเป้า AI agent เป็นกลุ่มผู้ใช้หลัก นี่คือความได้เปรียบเชิงกลยุทธ์

## Milestones

### M1 — Infrastructure พร้อมใช้งาน · สิ้นเมษายน 2026

**สิ่งที่ส่งมอบ:**
- `scripts/quickstart.sh` — ตั้งค่าด้วยคำสั่งเดียวสำหรับผู้ใช้ใหม่ (idempotent)
- `QUICKSTART.md` — คู่มือ visual สำหรับ 15 นาทีแรก
- Difficulty badge + ตัวอย่าง "สิ่งที่จะสร้าง" ในทุก 10 โมดูล
- `WHATS-NEW.md` + version badge ในทุกโมดูล
- `.github/workflows/staleness-check.yml` — สร้าง GitHub Issue รายสัปดาห์หากโมดูลไม่ได้รับการยืนยันมากกว่า 30 วัน
- Root `CLAUDE.md` — การกำหนดค่าของโปรเจกต์นี้เองเป็นตัวอย่างแนวปฏิบัติที่ดี
- `scripts/build-agent-index.py` — generator ที่อ่านทุกโมดูล → ส่งออก `agent-manifest.json` + `AGENT-INDEX.md`
- **06-hooks** — ปรับปรุงเชิงลึก: script hook ครบ 5 ชุด, decision tree, Try It Now, pattern
- **08-checkpoints** — ปรับปรุงเชิงลึก: จาก 311 → 800+ บรรทัด, workflow template 3 แบบ, decision tree, pattern

**เหตุผลที่เริ่มที่นี่:** Infrastructure เป็นประโยชน์ต่อทุก phase ในอนาคต Hooks และ checkpoints คือโมดูลที่อ่อนแอที่สุดและมีโอกาสสูญเสียผู้ใช้ใหม่มากที่สุด
