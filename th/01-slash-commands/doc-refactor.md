# การปรับโครงสร้างเอกสาร

ปรับโครงสร้างเอกสารโครงการให้เหมาะสมตามประเภทโครงการ:

1. **วิเคราะห์โครงการ**: ระบุประเภท (library/API/web app/CLI/microservices) สถาปัตยกรรม และกลุ่มผู้ใช้
2. **รวมศูนย์เอกสาร**: ย้ายเอกสารเทคนิคไปที่ `docs/` พร้อม cross-references ที่เหมาะสม
3. **Root README.md**: ปรับให้กระชับในฐานะจุดเข้าถึงหลัก ประกอบด้วย ภาพรวม quickstart สรุปโมดูล/คอมโพเนนต์ ใบอนุญาต และข้อมูลติดต่อ
4. **เอกสารคอมโพเนนต์**: เพิ่มไฟล์ README ในระดับโมดูล/แพ็กเกจ/บริการ พร้อมคำแนะนำการติดตั้งและการทดสอบ
5. **จัดระเบียบ `docs/`** ตามหมวดหมู่ที่เกี่ยวข้อง:
   - สถาปัตยกรรม, API Reference, ฐานข้อมูล, การออกแบบ, การแก้ปัญหา, การ deployment, การมีส่วนร่วม (ปรับตามความต้องการโครงการ)
6. **สร้าง guide** (เลือกที่เกี่ยวข้อง):
   - User Guide: เอกสารสำหรับผู้ใช้ปลายทาง
   - API Documentation: endpoints, authentication, ตัวอย่างสำหรับ API
   - Development Guide: การติดตั้ง การทดสอบ workflow การมีส่วนร่วม
   - Deployment Guide: การ deployment สำหรับ production สำหรับบริการ/แอปพลิเคชัน
7. **ใช้ Mermaid** สำหรับแผนภาพทั้งหมด (สถาปัตยกรรม flows schemas)

เก็บเอกสารให้กระชับ อ่านง่าย และสอดคล้องกับประเภทโครงการ
