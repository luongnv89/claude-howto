# Code Review Checklist

## Security Checklist
- [ ] 하드코딩된 자격 증명이나 비밀 키가 없을 것
- [ ] 모든 사용자 입력에 대해 입력값 검증을 수행할 것
- [ ] SQL 인젝션 방지 (파라미터화된 쿼리 사용)
- [ ] 상태를 변경하는 작업에 CSRF 방지 적용
- [ ] 적절한 이스케이프 처리를 통해 XSS 방지
- [ ] 보호된 엔드포인트에 대해 인증 확인 절차를 거칠 것
- [ ] 리소스에 대한 인가 확인 절차를 거칠 것
- [ ] 안전한 비밀번호 해싱 알고리즘(bcrypt, argon2)을 사용할 것
- [ ] 로그에 민감한 데이터를 남기지 않을 것
- [ ] HTTPS 연결을 강제할 것

## Performance Checklist
- [ ] N+1 쿼리가 없을 것
- [ ] 인덱스를 적절하게 활용할 것
- [ ] 이점이 있는 곳에 캐싱을 구현할 것
- [ ] 메인 스레드에서 블로킹 작업이 발생하지 않도록 할 것
- [ ] async/await가 올바르게 사용되었을 것
- [ ] 대용량 데이터 세트에 페이지네이션을 적용할 것
- [ ] 데이터베이스 커넥션 풀을 사용할 것
- [ ] 정규 표현식이 최적화되어 있을 것
- [ ] 불필요한 객체 생성을 지양할 것
- [ ] 메모리 누수를 방지할 것

## Quality Checklist
- [ ] 함수의 길이가 50줄 미만일 것
- [ ] 변수명이 명확할 것
- [ ] 중복 코드가 없을 것
- [ ] 올바른 에러 처리가 되어 있을 것
- [ ] 주석은 무엇을(WHAT)이 아니라 왜(WHY) 그렇게 했는지 설명할 것
- [ ] 프로덕션 환경에 console.logs를 남기지 않을 것
- [ ] 타입 검사(TypeScript/JSDoc)가 적용되어 있을 것
- [ ] SOLID 원칙을 준수할 것
- [ ] 디자인 패턴이 올바르게 적용되었을 것
- [ ] 코드 자체로 설명이 되는 코드를 지향할 것

## Testing Checklist
- [ ] 유닛 테스트가 작성되어 있을 것
- [ ] 예외 케이스들이 커버되었을 것
- [ ] 에러 시나리오가 테스트되었을 것
- [ ] 통합 테스트가 존재할 것
- [ ] 테스트 커버리지가 80% 이상일 것
- [ ] 불안정한 테스트가 없을 것
- [ ] 외부 의존성은 모킹 처리할 것
- [ ] 테스트 이름이 명확할 것
