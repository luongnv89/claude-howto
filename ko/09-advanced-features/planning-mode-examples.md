```

## 블로그 REST API 구현 계획

### 1단계: 프로젝트 설정 (15분)
1. Node.js + Express 프로젝트 초기화

### 2단계: 데이터베이스 계층 (30분)
6. DB 스키마 설계
   - users 테이블 (id, email, password_hash, created_at)
   - posts 테이블 (id, user_id, title, content, published, created_at, updated_at)
   - comments 테이블 (id, post_id, user_id, content, created_at)
7. 마이그레이션 파일 생성
8. DB 연결 풀 구성
9. 모델 구현

### 3단계: 인증 (45분)
10. 회원가입 API
11. 로그인 API (JWT)
12. 인증 미들웨어
13. bcrypt 비밀번호 해싱
14. 토큰 갱신 로직

### 4단계: 게시글 API (40분)
15. GET /api/posts (페이지네이션)
16. GET /api/posts/:id
17. POST /api/posts (인증 필요)
18. PUT /api/posts/:id (권한 체크)
19. DELETE /api/posts/:id
20. GET /api/users/:id/posts

### 5단계: 댓글 API (30분)
21. 댓글 조회
22. 댓글 생성
23. 댓글 삭제

### 6단계: 검증 및 에러 처리 (30분)
24. Joi 검증
25. 글로벌 에러 핸들러
26. 입력 sanitization
27. rate limiting

### 7단계: 테스트 (60분)
28. 단위 테스트
29. 통합 테스트 (auth)
30. 통합 테스트 (posts)
31. 통합 테스트 (comments)
32. 테스트 커버리지 80%+

### 8단계: 문서 및 배포 (30분)
33. Swagger 문서 생성
34. README 작성
35. Docker 설정
36. CI/CD 구성

**예상 시간**: 4.5시간
**생성 파일 수**: 약 25개
**핵심 기술**: Express, PostgreSQL, JWT, TypeScript

**API 요약**:
- 인증: 2개
- 게시글: 6개
- 댓글: 3개
- 총 11개 엔드포인트
```

## 예제 3: 프론트엔드 리팩토링

```
### 1단계: 준비 및 분석 (2시간)

   - 복잡 (여러 lifecycle + refs): 약 8개 컴포넌트
3. 외부 라이브러리 의존성 확인
4. 컴포넌트 의존성 그래프 생성
5. 마이그레이션 순서 결정 (leaf node 우선)

### 2단계: 환경 설정 (1시간)
6. React v18+ 업그레이드
7. ESLint hooks 규칙 적용
8. 변환 템플릿 생성
9. 테스트 환경 구성
10. 시작 전 체크포인트 생성

### 3단계: 단순 컴포넌트 마이그레이션 (4시간)
11. 단순 state 컴포넌트 변환 (15개)
12. this.state → useState 변경
13. this.setState → setter 함수 변경
14. 각 컴포넌트 테스트
15. 테스트 코드 업데이트

### 4단계: 중간 컴포넌트 마이그레이션 (8시간)
16. lifecycle 포함 컴포넌트 변환 (23개)
17. componentDidMount → useEffect

20. 전체 테스트 수행

### 5단계: 복잡 컴포넌트 마이그레이션 (12시간)

### 6단계: 공통 로직 추출 (6시간)
26. 중복 로직 분석
27. custom hooks 생성:
   - useAuth
   - useFetch
   - useLocalStorage
   - useDebounce
28. 컴포넌트 리팩토링
29. hook 단위 테스트

### 7단계: 성능 최적화 (4시간)
30. React.memo 적용
31. useCallback 최적화
32. useMemo 적용
33. 성능 프로파일링 및 개선

### 8단계: 정리 및 문서화 (2시간)
34. 불필요한 class 유틸 제거
35. 문서 업데이트

37. 마이그레이션 가이드 작성

**수정 파일 수**: 46개 컴포넌트
**리스크 수준**: 중간

**마이그레이션 순서**
1. 의존성 없는 leaf 컴포넌트
2. 중간 레벨 컴포넌트
3. 상위 container 컴포넌트

**테스트 전략**
```

## 핵심 요약

### 계획 모드의 장점

1. **명확성**: 작업 시작 전에 명확한 로드맵을 수립
2. **예측 가능성**: 시간과 노력에 대한 예상 제공
3. **위험 평가**: 잠재적인 문제를 조기에 식별
4. **우선순위 설정**: 작업을 논리적인 순서로 구성
5. **승인 절차**: 실행 전에 검토 및 승인 가능
6. **수정 용이성**: 피드백을 반영하여 계획 조정 가능

### 계획 모드를 사용해야 하는 경우

✅ **항상 사용하는 것이 좋은 경우**:
- 며칠 이상 소요되는 프로젝트
- 팀 협업
- 중요한 시스템 변경
- 새로운 개념 학습
- 복잡한 리팩터링

❌ **사용하지 않아도 되는 경우**:
- 버그 수정
- 작은 변경 사항
- 단순한 질의
- 간단한 실험
