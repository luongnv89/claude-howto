# 보안 정책

## 개요
Claude How To 프로젝트의 보안은 매우 중요합니다. 이 문서는 프로젝트의 보안 관행을 설명하고, 보안 취약점을 책임감 있게 신고하는 방법을 안내합니다.

## 지원 버전
다음 버전에 대해 보안 업데이트를 제공합니다.

| Version | Status | Support Until |
|---------|--------|---------------|
| Latest (main) | ✅ Active | Current + 6 months |
| 1.x releases | ✅ Active | Until next major version |

**참고**: 이 프로젝트는 교육용 가이드 프로젝트이므로, 일반적인 버전 지원보다는 최신 모범 사례와 문서 보안을 유지하는 데 중점을 둡니다. 업데이트는 메인 브랜치에 직접 적용됩니다.

## 보안 관행

### 코드 보안

1. **의존성 관리**
   - 모든 Python 의존성은 `requirements.txt`에 고정되어 있습니다.
   - Dependabot 및 수동 검토를 통해 정기적으로 업데이트합니다.
   - 모든 커밋에서 Bandit을 사용해 보안 스캔을 수행합니다.
   - 보안 검사를 위한 pre-commit 훅을 사용합니다.

2. **코드 품질**
   - Ruff를 사용한 린트 검사가 일반적인 문제를 탐지합니다.
   - mypy를 통한 타입 검사는 타입 관련 취약점을 방지합니다.
   - pre-commit 훅이 표준 준수를 강제합니다.
   - 모든 변경 사항은 병합 전에 검토됩니다.

3. **접근 제어**
   - `main` 브랜치에 브랜치 보호가 적용됩니다.
   - 병합 전 필수 리뷰가 필요합니다.
   - 병합 전에 상태 검사(Status Checks)가 모두 통과해야 합니다.
   - 저장소 쓰기 권한은 제한적으로 부여됩니다.

### 문서 보안

1. **예제에 비밀 정보 포함 금지**
   - 예제에 포함된 모든 API 키는 자리 표시자(placeholder)입니다.
   - 자격 증명은 절대 하드코딩되지 않습니다.
   - `.env.example` 파일은 필요한 변수를 보여줍니다.
   - 비밀 정보 관리에 대한 명확한 경고를 제공합니다.

2. **보안 모범 사례**
   - 예제는 안전한 구현 패턴을 보여줍니다.
   - 보안 경고를 문서에서 강조 표시합니다.
   - 공식 보안 가이드 링크를 제공합니다.
   - 관련 섹션에서 자격 증명 처리 방법을 설명합니다.

3. **콘텐츠 검토**
   - 모든 문서는 보안 문제 여부를 검토합니다.
   - 기여 가이드라인에 보안 고려 사항이 포함됩니다.
   - 외부 링크와 참고 자료를 검증합니다.

### 의존성 보안

1. **스캔**
   - Bandit이 모든 Python 코드의 취약점을 검사합니다.
   - GitHub 보안 경고를 통해 의존성 취약점을 확인합니다.
   - 정기적으로 수동 보안 감사를 수행합니다.

2. **업데이트**
   - 보안 패치는 신속하게 적용됩니다.
   - 메이저 버전은 신중하게 평가합니다.
   - 변경 이력에는 보안 관련 업데이트가 포함됩니다.

3. **투명성**
   - 보안 업데이트는 커밋에 문서화됩니다.
   - 취약점 공개는 책임감 있게 처리합니다.
   - 필요 시 공개 보안 권고문을 발행합니다.

### 중요하게 다루는 보안 이슈

다음과 같은 보고를 환영합니다.
- **스크립트 또는 예제 코드의 취약점**
- **Python 패키지의 의존성 취약점**
- **코드 예제의 암호화 관련 문제**
- **문서 내 인증/인가 취약점**
- **설정 예제의 데이터 노출 위험**

- **SSRF/XXE/경로 순회(Path Traversal) 문제**

### 범위에 포함되지 않는 보안 이슈

다음 항목은 이 프로젝트의 범위에 포함되지 않습니다.
- Claude Code 자체의 취약점(Anthropic에 신고)

- 개념 증명(PoC) 없이 제시된 이론적 취약점
- 공식 채널을 통해 이미 보고된 의존성 취약점

## 신고 방법

### 비공개 신고 (권장)

**민감한 보안 이슈는 GitHub의 비공개 취약점 신고 기능을 이용해 주세요.**

1. 방문: https://github.com/luongnv89/claude-howto/security/advisories
2. "Report a vulnerability" 클릭
3. 취약점 세부 정보 입력
4. 다음 정보를 포함:
   - 취약점에 대한 명확한 설명
   - 영향을 받는 구성 요소(파일, 섹션, 예제)
   - 잠재적 영향
   - 재현 방법(해당하는 경우)
   - 제안하는 수정 방법(있는 경우)

**이후 진행 절차**
- 48시간 이내에 접수 사실을 확인합니다.
- 취약점을 조사하고 심각도를 평가합니다.
- 수정 방안을 함께 마련합니다.
- 공개 일정을 조율합니다.
- 원하실 경우 보안 권고문에 기여자로 이름을 표기합니다.

### 공개 신고

민감하지 않거나 이미 공개된 이슈의 경우:

1. `security` 라벨을 사용하여 GitHub Issue를 생성합니다.
2. 다음 정보를 포함합니다.
   - 제목: `[SECURITY]` 뒤에 간단한 설명
   - 상세 설명
   - 영향을 받는 파일 또는 섹션
   - 잠재적 영향
   - 제안하는 수정 방법


## 취약점 대응 절차

### 평가 (24시간 이내)

1. 보고서 접수를 확인합니다.
2. [CVSS v3.1](https://www.first.org/cvss/v3.1/specification-document)을 사용하여 심각도를 평가합니다.
3. 범위 내 이슈인지 확인합니다.
4. 초기 평가 결과를 전달합니다.

### 수정 개발 (1~7일)

1. 수정 사항을 개발합니다.
2. 수정 사항을 검토하고 테스트합니다.
3. 보안 권고문을 작성합니다.
4. 릴리스 노트를 준비합니다.

### 공개 (심각도에 따라 상이)

**치명적(Critical) (CVSS 9.0-10.0)**
- 즉시 수정 버전 배포
- 공개 보안 권고문 발행
- 신고자에게 24시간 사전 통지

**높음(High) (CVSS 7.0-8.9)**
- 48~72시간 내 수정 버전 배포
- 신고자에게 5일 사전 통지
- 릴리스 시 공개 권고문 발행

**보통(Medium) (CVSS 4.0-6.9)**
- 다음 정기 업데이트에 포함
- 릴리스 시 공개 권고문 발행

**낮음(Low) (CVSS 0.1-3.9)**
- 다음 정기 업데이트에 포함
- 릴리스 시 권고문 발행


### 게시

발행되는 보안 권고문에는 다음이 포함됩니다.
- 취약점 설명
- 영향을 받는 구성 요소
- 심각도 평가(CVSS 점수)
- 수정 버전
- 우회 방법(해당하는 경우)
- 신고자 크레딧(동의한 경우)

## 신고자를 위한 모범 사례

### 신고 전

- **이슈 검증**: 일관되게 재현 가능한가요?
- **기존 이슈 검색**: 이미 보고된 문제인가요?
- **문서 확인**: 안전한 사용 방법이 안내되어 있나요?
- **수정안 테스트**: 제안한 수정 방법이 실제로 동작하나요?

### 신고 시

- **구체적으로 작성**: 정확한 파일 경로와 줄 번호를 제공하세요.
- **맥락 제공**: 왜 이것이 보안 문제인지 설명하세요.
- **영향 설명**: 공격자가 무엇을 할 수 있는지 설명하세요.
- **재현 절차 제공**: 어떻게 재현할 수 있는지 설명하세요.
- **수정안 제안**: 어떻게 수정할 수 있을지 제안하세요.

### 신고 후

- **인내심을 가져주세요**: 프로젝트의 리소스는 제한적입니다.
- **신속히 응답해 주세요**: 후속 질문에 빠르게 답변해 주세요.
- **기밀을 유지해 주세요**: 수정 전에는 공개하지 말아 주세요.
- **조율을 존중해 주세요**: 공개 일정에 협조해 주세요.

## 보안 헤더 및 구성

### 저장소 보안

- **브랜치 보호**: 메인 브랜치 변경 시 2명의 승인 필요
- **상태 검사**: 모든 CI/CD 검사를 통과해야 함
- **CODEOWNERS**: 주요 파일에 대한 지정 리뷰어 운영
- **서명된 커밋**: 기여자에게 권장

### 개발 보안

```bash
# Install pre-commit hooks
pre-commit install

# Run security scans locally
bandit -c pyproject.toml -r scripts/
mypy scripts/ --ignore-missing-imports
ruff check scripts/
```

### 의존성 보안

```bash
# Check for known vulnerabilities
pip install safety
safety check

# Or use pip-audit
pip install pip-audit
pip-audit
```

## 기여자를 위한 보안 가이드라인

### 예제 작성 시

1. **비밀 정보를 절대 하드코딩하지 마세요**
   ```python
   # ❌ Bad
   api_key = "sk-1234567890"

   # ✅ Good
   api_key = os.getenv("API_KEY")
   ```

2. **보안 영향을 경고하세요**
   ```markdown
   ⚠️ **Security Note**: Never commit `.env` files to git.
   Add to `.gitignore` immediately.
   ```

3. **안전한 기본값을 사용하세요**
   - 기본적으로 인증을 활성화합니다.
   - 가능한 경우 HTTPS를 사용합니다.
   - 입력값을 검증하고 정제합니다.
   - 매개변수화된 쿼리를 사용합니다.

4. **보안 고려 사항을 문서화하세요**
   - 보안이 중요한 이유를 설명합니다.
   - 안전한 패턴과 안전하지 않은 패턴을 비교하여 보여줍니다.
   - 신뢰할 수 있는 공식 자료를 연결합니다.
   - 경고 사항을 눈에 띄게 표시합니다.

### 기여 내용 검토 시

1. **노출된 비밀 정보를 확인하세요**
   - 일반적인 패턴(`api_key=`, `password=` 등)을 검사합니다.
   - 설정 파일을 검토합니다.
   - 환경 변수를 확인합니다.

2. **안전한 코딩 관행을 검증하세요**
   - 하드코딩된 자격 증명이 없는지 확인
   - 적절한 입력 검증 수행
   - 안전한 인증 및 권한 부여 적용
   - 안전한 파일 처리 구현

3. **보안 영향을 테스트하세요**
   - 악용될 가능성이 있는가?
   - 최악의 시나리오는 무엇인가?
   - 고려해야 할 예외 상황이 있는가?
