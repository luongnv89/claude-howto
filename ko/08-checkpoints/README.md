# 체크포인트 및 되감기

체크포인트를 사용하면 Claude Code 세션에서 대화 상태를 저장하고 이전 시점으로 되돌릴 수 있습니다. 이는 다양한 접근 방식을 실험하거나, 실수를 복구하거나, 여러 해결 방법을 비교하는 데 매우 유용합니다.

## 개요

체크포인트는 대화 상태를 저장하고 이전 시점으로 되돌릴 수 있게 해주는 기능입니다. 이를 통해 안전하게 다양한 접근 방식을 실험하고 탐색할 수 있습니다. 체크포인트에는 다음이 포함됩니다:

- 모든 메시지 기록
- 파일 수정 내역
- 도구 사용 기록
- 세션 컨텍스트

체크포인트는 다양한 접근 방식을 탐색하거나, 실수를 복구하거나, 대안들을 비교할 때 매우 유용합니다.

## 핵심 개념

| 개념 | 설명 |
|------|------|
| **체크포인트** | 메시지, 파일, 컨텍스트를 포함한 대화 상태의 스냅샷 |
| **되감기(Rewind)** | 체크포인트 시점으로 돌아가 이후 변경 사항을 폐기 |
| **브랜치 포인트** | 여러 접근 방식을 탐색하기 위한 기준 체크포인트 |

## 체크포인트 접근 방법

체크포인트는 두 가지 방법으로 접근할 수 있습니다:

### 키보드 단축키 사용
`Esc` 키를 두 번 누르면(`Esc` + `Esc`) 체크포인트 인터페이스가 열리며 저장된 체크포인트를 탐색할 수 있습니다.

### 슬래시 명령어 사용
빠른 접근을 위해 `/rewind` 명령어(별칭: `/checkpoint`)를 사용할 수 있습니다:

```bash
# 되감기 인터페이스 열기
/rewind

# 별칭 사용
/checkpoint
```

## 되감기 옵션

되감기를 수행하면 다음 5가지 옵션이 제공됩니다:

1. **코드와 대화 복원** -- 파일과 메시지를 해당 체크포인트 상태로 모두 복원
2. **대화만 복원** -- 메시지만 되돌리고 파일은 현재 상태 유지
3. **코드만 복원** -- 파일만 되돌리고 대화 기록은 유지
4. **여기서부터 요약** -- 선택 시점 이후의 대화를 AI가 생성한 요약으로 압축하여 컨텍스트 공간을 확보. 이전 메시지는 유지되며 디스크 파일은 변경되지 않음. 원본 메시지는 세션에 보존됨. 필요 시 특정 주제 중심으로 요약 가능
5. **취소** -- 작업을 취소하고 현재 상태로 복귀

> **참고**: 대화 복원 또는 요약 후에는 선택한 메시지의 원본 프롬프트가 입력창에 복원되어 다시 전송하거나 수정할 수 있습니다.

> **`/clear`는 더 이상 강한 경계가 아님 (v2.1.191+)**: `/rewind`를 사용하면 `/clear` 이전 시점으로도 되돌아갈 수 있습니다. 이제 clear 이후에도 이전 상태로 복귀가 가능합니다.

## 자동 체크포인트

Claude Code는 자동으로 체크포인트를 생성합니다:

- **모든 사용자 입력마다** 체크포인트 생성
- **영구 저장**: 세션 간 유지됨
- **자동 정리**: 30일 후 자동 삭제

따라서 몇 분 전부터 며칠 전까지 모든 시점으로 되돌아갈 수 있습니다.

## 사용 사례

| 시나리오 | 워크플로우 |
|----------|------------|
| **다양한 접근 방식 탐색** | 저장 → A 시도 → 저장 → 되감기 → B 시도 → 비교 |
| **안전한 리팩토링** | 저장 → 리팩토링 → 테스트 → 실패 시 되감기 |
| **A/B 테스트** | 저장 → A 설계 → 저장 → 되감기 → B 설계 → 비교 |
| **실수 복구** | 문제 발견 → 마지막 정상 상태로 되감기 |

## 체크포인트 사용 방법

### 확인 및 되감기

`Esc`를 두 번 누르거나 `/rewind`를 입력하면 체크포인트 브라우저가 열립니다. 시간순으로 모든 체크포인트가 표시되며 원하는 시점을 선택해 되돌릴 수 있습니다.

### 체크포인트 상세 정보

각 체크포인트에는 다음 정보가 포함됩니다:
- 생성 시간
- 수정된 파일 목록
- 대화 메시지 수
- 사용된 도구 목록

## 실전 예시

### 예시 1: 다양한 접근 방식 탐색

```
User: API에 캐싱 레이어를 추가해줘

Claude: Redis 캐싱을 API에 추가하겠습니다...
[A 시점 체크포인트 생성 후 변경 수행]

User: 아니, 인메모리 캐싱으로 해보자

Claude: 다른 접근 방식을 위해 되감기합니다...
[Esc+Esc로 A 체크포인트로 되감기]
[인메모리 캐싱 적용]

User: 이제 두 방식 비교할 수 있겠다
```

### 예시 2: 실수 복구

```
User: 인증 모듈을 JWT로 리팩토링해줘

Claude: 인증 모듈을 리팩토링합니다...
[대규모 변경 수행]

User: 잠깐, OAuth가 깨졌어. 되돌리자

Claude: 리팩토링 이전 상태로 되감겠습니다...
[리팩토링 이전 체크포인트로 복귀]

User: 이번엔 더 안전하게 해보자
```

### 예시 3: 안전한 실험

```
User: 함수형 스타일로 다시 작성해보자
[실험 시작 전 체크포인트 생성]

Claude: 함수형 스타일로 변경 중...

User: 테스트 실패했어. 되돌리자
[체크포인트로 복귀]

Claude: 이전 상태로 복원했습니다. 다른 접근을 시도해보겠습니다.
```

### 예시 4: 브랜치 비교

```
User: 두 가지 DB 설계를 비교하고 싶어
[시작 체크포인트]

Claude: 첫 번째 설계 구현...
[스키마 A 구현]

User: 다시 돌아가서 두 번째 방식도 해보자
[시작 체크포인트로 되감기]

Claude: 스키마 B 구현...
[스키마 B 구현]

User: 이제 두 가지 비교 가능
```

## 체크포인트 보관 정책

Claude Code는 체크포인트를 자동 관리합니다:

- 모든 사용자 입력마다 자동 생성
- 최대 30일간 보관
- 오래된 체크포인트는 자동 삭제

## 워크플로 패턴

### 탐색을 위한 브랜칭 전략

여러 접근 방식을 비교할 때:

```
1. 초기 상태 → 체크포인트 A
2. 방법 1 시도 → 체크포인트 B
3. A로 되감기
4. 방법 2 시도 → 체크포인트 C
5. B와 C 비교
6. 최종 선택 후 진행
```

### 안전한 리팩토링 패턴

큰 변경을 할 때:

```
1. 현재 상태 → 자동 체크포인트
2. 리팩토링 시작
3. 테스트 실행
4. 성공 → 계속 진행
5. 실패 → 되감기 후 다른 접근 시도
```

## 모범 사용법

체크포인트는 자동 생성되므로 별도 저장 없이 작업할 수 있습니다. 하지만 다음 원칙을 권장합니다:

### 효과적인 사용법

✅ **권장**
- 되감기 전 체크포인트 목록 확인
- 다른 방향을 실험할 때 rewind 활용
- 여러 접근 방식 비교에 활용
- 각 옵션의 의미 정확히 이해

❌ **비권장**
- 체크포인트를 코드 저장소처럼 의존
- 외부 파일 변경 추적 용도로 사용
- Git 커밋 대체 수단으로 사용

## 구성(Configuration)

체크포인트는 Claude Code의 기본 내장 동작이며, 별도의 설정 없이 자동으로 활성화됩니다. 모든 사용자 입력마다 자동으로 체크포인트가 생성됩니다.

체크포인트와 관련된 유일한 설정은 `cleanupPeriodDays`이며, 이는 세션 및 체크포인트가 유지되는 기간을 제어합니다:

```json
{
  "cleanupPeriodDays": 30
}
```

- `cleanupPeriodDays`: 세션 기록 및 체크포인트를 보관하는 기간 (기본값: `30`일)

> **v2.1.117 업데이트**: `cleanupPeriodDays`는 이제 체크포인트뿐만 아니라 다음 4가지 디스크 캐시 전체를 관리합니다:
>
> - 세션 체크포인트
> - `~/.claude/tasks/` — 영구 작업 리스트
> - `~/.claude/shell-snapshots/` — 셸 환경 스냅샷
> - `~/.claude/backups/` — 설정 및 CLAUDE.md 백업 롤링 저장소
>
> 하나의 설정값으로 위 4개 디렉토리가 동일한 보관 기간 기준으로 정리됩니다.

## 제한사항(Limitations)

체크포인트에는 다음과 같은 제한이 있습니다:

- **bash 명령 변경은 추적되지 않음** - `rm`, `mv`, `cp` 같은 파일 시스템 작업은 체크포인트에 포함되지 않음
- **외부 변경은 추적되지 않음** - Claude Code 외부(에디터, 터미널 등)에서 발생한 변경은 기록되지 않음
- **버전 관리 시스템 대체 불가** - 영구적이고 감사 가능한 변경 이력은 Git을 사용해야 함

## 문제 해결(Troubleshooting)

### 체크포인트가 보이지 않음

**문제**: 예상한 체크포인트가 없음

**해결 방법**:
- 체크포인트가 정리되었는지 확인
- 디스크 공간 확인
- `cleanupPeriodDays` 값이 충분히 큰지 확인 (기본 30일)

### 되감기 실패

**문제**: 체크포인트로 되돌아갈 수 없음

**해결 방법**:
- 커밋되지 않은 변경 사항 충돌 여부 확인
- 체크포인트 손상 여부 확인
- 다른 체크포인트로 되감기 시도

## Git과의 통합

체크포인트는 Git을 대체하지 않고 보완하는 기능입니다:

| 기능 | Git | 체크포인트 |
|------|-----|------------|
| 범위 | 파일 시스템 | 대화 + 파일 |
| 지속성 | 영구적 | 세션 기반 |
| 세분화 | 커밋 단위 | 모든 시점 |
| 속도 | 상대적으로 느림 | 즉시 |
| 공유 | 가능 | 제한적 |

둘을 함께 사용하는 것이 권장됩니다:
1. 빠른 실험에는 체크포인트 사용
2. 확정된 변경은 Git 커밋 사용
3. Git 작업 전 체크포인트 생성
4. 성공한 상태를 Git에 저장

## 빠른 시작 가이드(Quick Start Guide)

### 기본 워크플로우

1. **일반적으로 작업** - Claude Code가 자동으로 체크포인트 생성
2. **되돌리고 싶을 때** - `Esc` 두 번 또는 `/rewind` 사용
3. **체크포인트 선택** - 목록에서 원하는 시점 선택
4. **복원 방식 선택** - 코드와 대화 복원, 대화만 복원, 코드만 복원, 여기서부터 요약, 취소 중 선택
5. **작업 계속** - 해당 시점에서 다시 작업 진행

### 키보드 단축키

- **`Esc` + `Esc`** - 체크포인트 브라우저 열기
- **`/rewind`** - 체크포인트 접근 명령어
- **`/checkpoint`** - `/rewind`의 별칭

## 되감기를 언제 해야 하는가: 컨텍스트 모니터링

체크포인트는 되돌릴 수 있게 해주지만, *언제 되돌려야 하는지*도 중요합니다. 대화가 길어질수록 Claude의 컨텍스트 윈도우가 차게 되고, 모델 성능이 점진적으로 저하될 수 있습니다. 이때 사용자는 인지하지 못한 상태에서 품질이 낮아진 결과를 기반으로 코드를 생성할 수 있습니다.

**[cc-context-stats](https://github.com/luongnv89/cc-context-stats)**는 이를 해결하기 위해 Claude Code 상태바에 실시간 **컨텍스트 구간 표시**를 제공합니다. 컨텍스트를 세 구간으로 나누어 보여줍니다:

- **Plan (초록)**: 안전한 계획 및 개발 단계
- **Code (노랑)**: 새로운 계획 시작은 피해야 하는 단계
- **Dump (주황)**: 마무리하고 되감기가 필요한 단계

이 구간이 변경되면 체크포인트를 만들고 새로 시작하는 것이 권장됩니다.

## 요약(Summary)

체크포인트는 Claude Code의 자동 기능으로, 작업을 잃지 않고 다양한 접근 방식을 안전하게 실험할 수 있게 해줍니다. 모든 사용자 입력마다 자동으로 체크포인트가 생성되므로 언제든지 이전 시점으로 되돌릴 수 있습니다.

핵심 장점:
- 여러 접근 방식을 자유롭게 실험 가능
- 실수 발생 시 빠른 복구
- 다양한 해결책 비교 가능
- Git과 안전하게 함께 사용 가능

중요: 체크포인트는 Git을 대체하지 않습니다. 빠른 실험에는 체크포인트를, 확정된 변경에는 Git을 사용하세요.
