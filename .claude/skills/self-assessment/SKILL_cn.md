# 自我评估与学习路径顾问

全面的互动评估，评估 Claude Code 在 10 个功能领域的熟练程度，识别具体技能差距，并生成个性化学习路径以帮助提升。

## 说明

### 第 1 步：欢迎并选择评估模式

向用户呈现评估深度选择：

使用 AskUserQuestion，提供以下选项：
- **快速评估** — "8 道题，约 2 分钟。确定您的整体水平（初学者/中级/高级）并给出学习路径。"
- **深度评估** — "5 个类别的详细题目，约 5 分钟。提供按主题技能分数，识别具体差距，并构建优先学习路径。"

如果用户选择**快速评估**，跳转到步骤 2A。
如果用户选择**深度评估**，跳转到步骤 2B。

---

### 步骤 2A：快速评估

呈现两道多选题（AskUserQuestion 每题最多支持 4 个选项）：

**问题 1**（标题："Basics"）：
"第 1/2 部分：您已掌握哪些 Claude Code 技能？"
选项：
1. "启动 Claude Code 并聊天" — 我能运行 `claude` 并与它交互
2. "创建/编辑了 CLAUDE.md" — 我已设置项目或用户记忆
3. "使用了 3+ 个斜线命令" — 例如 /help、/compact、/model、/clear
4. "创建了自定义命令/技能" — 编写了 SKILL.md 或自定义命令文件

**问题 2**（标题："Advanced"）：
"第 2/2 部分：您具备哪些高级技能？"
选项：
1. "配置了 MCP 服务器" — 例如 GitHub、数据库或其他外部数据源
2. "设置了 hooks" — 在 ~/.claude/settings.json 中配置了 hooks
3. "创建/使用了子代理" — 使用 .claude/agents/ 进行任务委派
4. "使用了打印模式（claude -p）" — 将 `claude -p` 用于非交互式或 CI/CD 使用

**评分：**
- 0-2 总计 = 第 1 级：初学者
- 3-5 总计 = 第 2 级：中级
- 6-8 总计 = 第 3 级：高级

跳转到步骤 3，将未选中的具体项目列为差距。

---

### 步骤 2B：深度评估

呈现 5 轮问题，每轮一次 AskUserQuestion 调用。每轮涵盖 2 个相关功能领域。所有轮次使用多选。

**重要**：AskUserQuestion 每题最多支持 4 个选项。每轮恰好有 1 道题，4 个选项涵盖 2 个主题（每个主题 2 个选项）。

---

**第 1 轮 — 斜线命令与记忆**（标题："Commands"）

"您做过以下哪些事情？请选择所有适用项。"
选项：
1. "创建了自定义斜线命令或技能" — 编写了包含 frontmatter 的 SKILL.md 文件，或创建了 .claude/commands/ 文件
2. "在命令中使用了动态上下文" — 在技能/命令文件中使用了 `$ARGUMENTS`、`$0`/`$1`、反引号 `!command` 语法或 `@file` 引用
3. "设置了项目 + 个人记忆" — 创建了项目 CLAUDE.md 和个人 ~/.claude/CLAUDE.md（或 CLAUDE.local.md）
4. "使用了记忆层次结构功能" — 了解 7 级优先顺序，使用了 .claude/rules/ 目录、路径特定规则或 @import 语法

**第 1 轮评分：**
- 选项 1-2 对应**斜线命令**（0-2 分）
- 选项 3-4 对应**记忆**（0-2 分）

---

**第 2 轮 — 技能与 Hooks**（标题："Automation"）

"您做过以下哪些事情？请选择所有适用项。"
选项：
1. "安装并使用了自动调用技能" — 一个根据其描述自动触发的技能，无需手动 /command 调用
2. "控制了技能调用行为" — 在 SKILL.md frontmatter 中使用了 `disable-model-invocation`、`user-invocable` 或包含 agent 字段的 `context: fork`
3. "设置了 PreToolUse 或 PostToolUse hook" — 配置了在工具执行前/后运行的 hook（例如命令验证器、自动格式化器）
4. "使用了高级 hook 功能" — 配置了提示类型 hooks、SKILL.md 中组件范围 hooks、HTTP hooks 或带自定义 JSON 输出的 hooks（updatedInput、systemMessage）

**第 2 轮评分：**
- 选项 1-2 对应**技能**（0-2 分）
- 选项 3-4 对应 **Hooks**（0-2 分）

---

**第 3 轮 — MCP 与子代理**（标题："Integration"）

"您做过以下哪些事情？请选择所有适用项。"
选项：
1. "连接了 MCP 服务器并使用其工具" — 例如用于 PR/issues 的 GitHub MCP、用于查询的数据库 MCP 或任何外部数据源
2. "使用了高级 MCP 功能" — 项目范围 .mcp.json、OAuth 认证、带 @mentions 的 MCP 资源、工具搜索或 `claude mcp serve`
3. "创建或配置了自定义子代理" — 在 .claude/agents/ 中定义了具有自定义工具、模型或权限的代理
4. "使用了高级子代理功能" — 工作区隔离、持久代理记忆、Ctrl+B 后台任务、带 `Task(agent_name)` 的代理白名单或代理团队

**第 3 轮评分：**
- 选项 1-2 对应 **MCP**（0-2 分）
- 选项 3-4 对应**子代理**（0-2 分）

---

**第 4 轮 — 检查点与高级功能**（标题："Power User"）

"您做过以下哪些事情？请选择所有适用项。"
选项：
1. "使用了检查点进行安全实验" — 创建了检查点，使用了 Esc+Esc 或 /rewind，恢复了代码和/或对话，或使用了摘要选项
2. "使用了规划模式或扩展思考" — 通过 /plan、Shift+Tab 或 --permission-mode plan 激活规划；用 Alt+T/Option+T 切换扩展思考
3. "配置了权限模式" — 通过 CLI 标志、键盘快捷键或设置使用了 acceptEdits、plan、dontAsk 或 bypassPermissions 模式
4. "使用了远程/桌面/Web 功能" — 使用了 `claude remote-control`、`claude --remote`、`/teleport`、`/desktop` 或带 `claude -w` 的工作区

**第 4 轮评分：**
- 选项 1 对应**检查点**（0-1 分）
- 选项 2-4 对应**高级功能**（0-3 分，上限 2 分）

---

**第 5 轮 — 插件与 CLI**（标题："Mastery"）

"您做过以下哪些事情？请选择所有适用项。"
选项：
1. "安装或创建了插件" — 使用了市场中的捆绑插件，或创建了包含 plugin.json 清单的 .claude-plugin/ 目录
2. "使用了插件高级功能" — 插件 hooks、插件 MCP 服务器、LSP 配置、插件命名空间命令或用于测试的 --plugin-dir 标志
3. "在脚本或 CI/CD 中使用了打印模式" — 将 `claude -p` 与 --output-format json、--max-turns 一起使用，管道输入，或集成到 GitHub Actions/CI 管道
4. "使用了高级 CLI 功能" — 会话恢复（-c/-r）、--agents 标志、用于结构化输出的 --json-schema、--fallback-model、--from-pr 或批处理循环

**第 5 轮评分：**
- 选项 1-2 对应**插件**（0-2 分）
- 选项 3-4 对应 **CLI**（0-2 分）

---

```markdown
| 领域 | 状态 |
```

#### 3B：深度评估结果

从 5 轮计算按主题分数。每个主题获得 0-2 分。然后呈现：

```markdown
## Claude Code 技能评估结果

### 总体水平：[第 1 级 / 第 2 级 / 第 3 级]
```

**深度评估总体水平计算：**
- 0-6 总分 = 第 1 级：初学者
- 7-13 总分 = 第 2 级：中级
- 14-20 总分 = 第 3 级：高级

### 第 4 步：生成个性化学习路径

根据评估结果生成专门针对用户差距的学习路径。**不要**只是重复通用等级路径 — 要进行调整。

#### 路径生成规则

1. **跳过已掌握的主题**：如果主题得分 2/2，不要在路径中包含它。
2. **按依赖顺序优先**：斜线命令在技能之前，记忆在子代理之前，等等。依赖顺序为：
   - 斜线命令（无依赖）-> 技能（依赖斜线命令）
   - 记忆（无依赖）-> 子代理（依赖记忆）
   - CLI 基础（无依赖）-> CLI 精通（依赖所有）
   - 检查点（无依赖）
   - Hooks（依赖斜线命令）
   - MCP（无依赖）-> 插件（依赖 MCP、技能、Hooks）
   - 高级功能（依赖所有之前的）
3. **对于得分 1/2 的主题**：推荐"深入探讨" — 链接到他们缺失的具体高级章节。
4. **估算时间**：只累加他们需要学习/复习的主题。
5. **分组成阶段**：将剩余主题组织成每阶段 2-3 个主题的逻辑阶段。

#### 路径输出格式

```markdown
### 您的个性化学习路径

**估算时间**：约 N 小时（根据您当前技能调整）

#### 阶段 1：[阶段名称]（约 N 小时）
[仅在这些领域有差距时]

**[主题名称]** — [从头学习 / 深入探讨高级功能]
- 教程：[教程目录链接]
- 重点：[他们需要的具体章节/概念]
- 关键练习：[一个具体练习]
- 完成标准：[具体的成功标准]

**[主题名称]** — ...

---

#### 阶段 2：[阶段名称]（约 N 小时）
...

---

### 推荐实践项目

根据您的差距，尝试这些真实世界练习来巩固学习：

1. **[项目名称]**：[结合 2-3 个差距主题的 1 行描述]
2. **[项目名称]**：[1 行描述]
3. **[项目名称]**：[1 行描述]
```

---

### 第 5 步：提供后续行动

呈现结果后，询问用户接下来想做什么：

使用 AskUserQuestion，提供以下选项：
- **开始学习** — "帮我现在开始学习路径中的第一个主题"
- **深入探讨差距** — "详细解释我的某个差距领域，让我在这里学习"
- **实践项目** — "设置一个涵盖我差距领域的实践项目"
- **重新评估** — "我想重新参加测验（也许是另一种模式）"

如果**开始学习**：读取第一个差距教程的 README.md，引导用户完成第一个练习。
如果**深入探讨差距**：询问哪个差距主题，然后读取相关教程 README.md 并解释关键概念，附带示例。
如果**实践项目**：设计一个结合 2-3 个差距主题的小项目，提供具体步骤。
如果**重新评估**：返回步骤 1。

## 错误处理

### 用户在某轮中未选择任何项目
将该轮主题视为 0 分。继续下一轮。

### 用户在任何轮次都未选择任何项目
分配第 1 级：初学者。鼓励从头开始。输出完整的第 1 级路径。

### 用户希望重新评估
从步骤 1 开始重新运行，进行全新评估。

### 用户不同意自己的水平
承认他们的偏好。询问他们认为自己属于哪个水平。为他们选择的水平呈现路径，并对他们可能遗漏的主题进行前提条件检查。

### 用户询问特定主题
如果用户在评估过程中说"告诉我关于 hooks 的事"或"我想学 MCP"，记录下来。呈现结果后，无论得分如何，在学习路径中突出显示该主题。
