# 课时测验

互动测验，测试对特定 Claude Code 课时的理解，提供 8-10 道题，逐题反馈，并识别需要复习的领域。

## 说明

### 第 1 步：确定课时

如果用户提供了课时作为参数（例如 `/lesson-quiz hooks` 或 `/lesson-quiz 03`），将其映射到课时目录：

**课时映射：**
- `01`、`slash-commands`、`commands` → 01-slash-commands
- `02`、`memory` → 02-memory
- `03`、`skills` → 03-skills
- `04`、`subagents`、`agents` → 04-subagents
- `05`、`mcp` → 05-mcp
- `06`、`hooks` → 06-hooks
- `07`、`plugins` → 07-plugins
- `08`、`checkpoints`、`checkpoint` → 08-checkpoints
- `09`、`advanced`、`advanced-features` → 09-advanced-features
- `10`、`cli` → 10-cli

如果未提供参数，使用 AskUserQuestion 呈现选择提示：

**问题 1**（标题："Lesson"）：
"您想测验哪个课时？"
选项：
1. "斜线命令（01）" — 自定义命令、技能、frontmatter、参数
2. "记忆（02）" — CLAUDE.md、记忆层次结构、规则、自动记忆
3. "技能（03）" — 渐进式披露、自动调用、SKILL.md
4. "子代理（04）" — 任务委派、代理配置、隔离

**问题 2**（标题："Lesson"）：
"您想测验哪个课时？（续）"
选项：
1. "MCP（05）" — 外部集成、传输、服务器、工具搜索
2. "Hooks（06）" — 事件自动化、PreToolUse、退出码、JSON I/O
3. "插件（07）" — 捆绑解决方案、市场、plugin.json
4. "更多课时..." — 检查点、高级功能、CLI

如果选择"更多课时..."，呈现：

**问题 3**（标题："Lesson"）：
"选择您的课时："
选项：
1. "检查点（08）" — 回溯、恢复、安全实验
2. "高级功能（09）" — 规划、权限、打印模式、思考
3. "CLI 参考（10）" — 标志、输出格式、脚本编写、管道

### 第 2 步：读取课时内容

读取课时 README.md 文件以刷新上下文：
- 读取文件：`<lesson-directory>/README.md`

然后使用 `references/question-bank.md` 中该课时的题库。题库为每个课时提供 10 道预编写题目，包含正确答案和解释。

### 第 3 步：呈现测验

询问用户测验时机背景：

使用 AskUserQuestion（标题："Timing"）：
"您是在课时的哪个阶段进行此测验？"
选项：
1. "之前（预测）" — 我还没读过课时，测试我的先验知识
2. "期间（进度检查）" — 我已经学了一部分课时
3. "之后（掌握检查）" — 我已完成课时，想验证理解情况

此背景影响结果的呈现方式（见第 5 步）。

### 第 4 步：分轮呈现题目

以每轮 2 道题的形式呈现题库中的 10 道题（共 5 轮）。每道题使用 AskUserQuestion，包含题目文本和 3-4 个答案选项。

**重要**：使用 AskUserQuestion，每道题最多 4 个选项，每轮 2 道题。

每轮呈现 2 道题。完成所有 5 轮后，进入评分。

**每轮题目格式：**

题库中的每道题包含：
- `question`：题目文本
- `options`：3-4 个答案选项（一个正确，在题库中标注）
- `correct`：正确答案标签
- `explanation`：答案正确的原因
- `category`：「概念型」或「实践型」

使用 AskUserQuestion 呈现每道题。记录用户的每道题回答。

### 第 5 步：评分并呈现结果

所有轮次结束后，计算得分并呈现结果。

**评分：**
- 每道正确题 = 1 分
- 满分 = 10 分

**等级标准：**
- 9-10：已掌握 — 理解优秀
- 7-8：熟练 — 掌握良好，有小缺口
- 5-6：进步中 — 已理解基础，需要复习
- 3-4：入门 — 存在重大缺口，建议复习
- 0-2：尚未掌握 — 从本课时开头重新学习

**输出格式：**

```markdown
## 课时测验结果：[课时名称]

**得分：N/10** — [等级标签]
**测验时机**：[课前 / 课中 / 课后]
**题目分布**：N 道概念题正确，N 道实践题正确

### 逐题结果

| # | 类别 | 题目（简短） | 您的答案 | 结果 |
|---|------|------------|---------|------|
| 1 | 概念型 | [缩略题目] | [他们的答案] | [正确 / 错误] |
| 2 | 实践型 | ... | ... | ... |
| ... | ... | ... | ... | ... |

### 错误答案 — 复习这些内容

[对每个错误答案，显示：]

**Q[N]：[完整题目文本]**
- 您的答案：[他们选择的]
- 正确答案：[正确选项]
- 解释：[为什么正确]
- 复习：[需要重读的课时 README 特定章节]

### [时机特定消息]

[如果课前]：
**预测得分：N/10。** 这给了您一个基线！重点学习您答错的主题。完成课时后，重新测验以衡量进步。

[如果课中]：
**进度检查：N/10。** [如果 7+：进步很好——继续学习！如果 4-6：在继续之前复习错误的主题。如果 <4：考虑从头重新阅读。]

[如果课后]：
**掌握检查：N/10。** [如果 9-10：您已掌握本课时！继续下一课。如果 7-8：快掌握了——复习错误的主题然后重测。如果 <7：多花时间学习课时，尤其是上面标注的章节。]

### 推荐下一步

[根据得分和时机：]
- [如果已掌握]：继续学习路线图中的下一课时：[下一课链接]
- [如果熟练]：复习这些特定章节，然后重测：[列出章节]
- [如果进步中或以下]：重读完整课时：[课时链接]。重点关注：[列出薄弱类别]
- [提供]："您想重测这个测验、尝试不同课时，还是获取特定主题的帮助？"
```

### 第 6 步：提供后续选项

呈现结果后，使用 AskUserQuestion：

"您接下来想做什么？"
选项：
1. "重测此测验" — 再试一次相同课时测验
2. "测验其他课时" — 切换到不同课时
3. "解释我答错的主题" — 获取错误答案的详细解释
4. "完成" — 结束测验

如果**重测**：返回第 4 步（跳过时机问题，使用相同时机）。
如果**测验其他课时**：返回第 1 步。
如果**解释主题**：询问哪个题号，然后从课时 README.md 相关章节读取并解释，附带示例。

## 错误处理

### 无效课时参数
如果参数不匹配任何课时，显示有效课时列表并请用户选择。

### 用户希望中途退出测验
如果用户在任何轮次中途表示想停止，呈现已回答题目的部分结果。

### 找不到课时 README
如果在预期路径找不到 README.md 文件，告知用户并建议检查仓库结构。
